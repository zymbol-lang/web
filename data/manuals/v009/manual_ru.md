# Руководство по Zymbol-Lang

> **Пересмотрено для v0.0.9 — 2026-09-07**

**Zymbol-Lang** — символический язык программирования. В его грамматике нет слов — каждая конструкция является символом. Работает одинаково на любом человеческом языке.

- Нет `if`, `while`, `return` — только `?`, `@`, `<~`
- Полный Unicode — идентификаторы на любом языке или эмодзи
- Независимость от человеческого языка — код везде одинаков

**Версия интерпретатора**: v0.0.9 | **Покрытие тестами**: 660/666 (три движка согласны, 0 расхождений)

## Переменные и Константы

```zymbol
x = 10              // изменяемая переменная
PI := 3.14159       // константа — повторное присваивание вызывает ошибку выполнения
имя = "Алиса"
активен = #1        // логическое истина
👋 := "Привет"
```

```zymbol
x = 10    // 10
x += 5    // 15
x -= 3    // 12
x *= 2    // 24
x /= 3    // 8
x %= 3    // 2
x ^= 2    // 4
x++       // 5
x--       // 4
```

`°` (знак градуса, U+00B0) автоматически инициализирует переменную её нейтральным значением при первом использовании:

```zymbol
числа = [3, 1, 4, 1, 5]
@ n:числа {
    °итог += n
}
>> итог ¶              // → 14
```

> `°перем` (префикс) закрепляется над циклом — результат доступен после `@`.
> `перем°` (суффикс) закрепляется внутри цикла — умирает по завершении цикла.

Инструкция, состоящая только из имени, читает переменную и отбрасывает значение, поэтому выдаёт предупреждение:

```zymbol
счётчик = 5
счётчик
```

Компилятор выдаёт такое предупреждение (его сообщения всегда на английском):

```text
warning: this statement does nothing: 'счётчик' is read and discarded
  = help: remove it, or use it — `>> name ¶` to print it
```

То есть: *«эта инструкция ничего не делает: 'счётчик' прочитан и отброшен»*.

## Типы Данных

| Тип | Литерал | Тег `#?` | Примечания |
|------|---------|----------|------------|
| Целое | `42`, `-7` | `###` | Безопасное целое: ±(2⁵³ − 1) |
| Плавающее | `3.14`, `1.5e10` | `##.` | IEEE-754 двойной |
| Строка | `"текст"` | `##"` | Интерполяция: `"Привет {имя}"` |
| Символ | `'A'` | `##'` | Один графема Unicode |
| Логический | `#1`, `#0` | `##?` | НЕ числовой — `#1 ≠ 1` |
| Массив | `[1, 2, 3]` | `##]` | Один тип, проверяется |
| Объявленная смесь | `#[1, "два"]` | `##[` | Тот же тип, что `[…]`, не проверяется |
| Кортеж | `(a, b)` | `##)` | Позиционный, неизменяемый |
| Словарь | `#(x: 1, y: 2)` | `##(` | Ключевой, изменяемый |
| Функция | ссылка на именованную функцию | `##()` | Первого класса; отображается `<funct/N>` |
| Лямбда | `x -> x * 2` | `##->` | Первого класса; отображается `<lambd/N>` |
| Единица | `##_` | `##_` | Отсутствие — null не существует |

```zymbol
>> 42#? ¶               // → (###, 2, 42)
>> [1, 2, 3]#? ¶        // → (##], 3, [1, 2, 3])
>> #(x: 1)#? ¶          // → (##(, 1, #(x: 1))
```

Целое, выходящее за безопасный диапазон, является перехватываемой ошибкой, а не молчаливым переполнением:

```zymbol
!? {
    >> (9007199254740991 + 1) ¶
} :! ##Range {
    >> "вне диапазона" ¶ // → вне диапазона
}
```

`##_` — это способ программы спросить, отсутствует ли что-то:

```zymbol
ничего() { }
значение = ничего()
>> (значение == ##_) ¶     // → #1
```

## Вывод и Ввод

```zymbol
имя = "Алиса"
итог = 3
>> "Привет" ¶             // → Привет
>> "a=" имя " b=" итог ¶ // → a=Алиса b=3
>> итог#? ¶            // → (###, 1, 3)
```

```zymbol
<< имя
<< "Введите ваше имя: " имя
<< ###(4) "Возраст: " возраст
```

**Посмотрите на форму двух символов.** `>>` указывает наружу: он извлекает данные из программы. `<<` указывает внутрь: он вводит данные в программу. Здесь нечего запоминать — стрелка показывает, в каком направлении движется информация, и та же идея возвращается в каждом символе, который что-то перемещает.

> `¶` и `\\` — эквивалентные символы новой строки. `>>` никогда не добавляет её автоматически.
> Спецификатор типа перед приглашением проверяет ввод и повторяет запрос до получения допустимого значения:
> `##.` Плавающее · `##.(T,D)` десятичное · `###(N)` Целое · `##"(N)` текст · `##'` один Символ.

На верхнем уровне файла `<~` — это код выхода программы:

```zymbol
>> "проверка" ¶      // → проверка
<~ 0
```

## Примитивы TUI

Операторы терминального интерфейса для интерактивных программ. Большинство требуют блок `>>| { }` (альтернативный экран + сырой режим).

```zymbol
>>| {
    >>!
    >>~ (1, 1, 0, 10) > "Выполняется"
    @~ 1000
    >>~ (2, 1) > "Готово."
}
```

```zymbol
>>| {
    [строки, столбцы] = >>?
    >>~ (1, 1) > "Терминал: " строки " x " столбцы
    <<| клавиша
    >>~ (2, 1) > "Нажато: " клавиша
}
```

Здесь видно, почему символы комбинируются, а не умножаются. Вы уже знаете, что `<<` — это ввод, а `?` — вопрос без обязательств. Только один символ новый:

- `|` — это **одна единица**, а не весь поток.

Благодаря этому оба клавиатурных оператора читаются сами по себе:

```text
<<        |             ?
ввод      одна единица  без обязательств

<<|   взять ОДНУ клавишу и ждать, пока она появится
<<|?  проверить, ЕСТЬ ли клавиша, и продолжить, если нет
```

То же самое с другой стороны: `>>` отправляет, `>>!` отправляет **принудительно** (очищает весь экран), а `>>?` **спрашивает** вместо записи (насколько велик терминал). Символ справа — тот, который меняет режим, и он всегда идёт последним.

> `>>!` очищает экран. `>>?` возвращает `(строки, столбцы)`. `@~ N` засыпает на N миллисекунд.
> `<<|` читает одно нажатие клавиши (блокирующее); `<<|?` опрашивает без блокировки (`'\0'` если нет).
> Клавиши со стрелками приходят декодированными как `'↑' '↓' '←' '→'`; ESC — это кодовая точка 27.
> Кортеж позиционированного вывода: `(строка, столбец, BKS, передний, задний)` — любой слот может быть опущен с запятой (`>>~ (,,, 196) > "красный"`).
> Маска BKS: `1`=Жирный, `2`=Курсив, `4`=Подчёркнутый. Палитра ANSI 256 цветов (`0`=по умолчанию терминала).

## Операторы

```zymbol
a = 10
b = 3
р1 = a + b    // 13
р2 = a - b    // 7
р3 = a * b    // 30
р4 = a / b    // 3  (целочисленное деление)
р5 = a % b    // 1
р6 = a ^ b    // 1000
```

```zymbol
a = 10
b = 3
с1 = a == b    // #0
с2 = a <> b    // #1
с3 = a < b     // #0
с4 = a >= b    // #1
л1 = #1 && #0  // #0
л2 = !#1       // #0
```

> `==` никогда не приводит: `"5" == 5` — это `#0`. Упорядочение приводит: `"5" > 4` — это `#1`, и `"४२" > 5` тоже — числовой текст в любом из 69 письменностей сравнивается как число.
> Функция равна только самой себе, никогда другой функции с тем же телом.

## Строки

```zymbol
имя = "Алиса"
n = 42
>> "Привет " имя " у вас " n ¶ // → Привет Алиса у вас 42
описание = "Привет {имя}, у вас {n}"
>> описание ¶              // → Привет Алиса, у вас 42
```

```zymbol
s = "Привет мир"
длина = s$#                  // 10
подстрока = s$[1..5]             // "Привет"
содержит = s$? "мир"          // #1
части = "a,b,c,d"$/ ','    // [a, b, c, d]
замена = s$~~["е":"ё"]        // "Прнвёт мнр"
линия = "─" $* 20
```

> `+` только для чисел. Для строк используйте смежное расположение или интерполяцию.
> `\{` и `\}` — литеральные фигурные скобки; экранирование симметрично.

## Управление Потоком

```zymbol
x = 7
? x > 100 {
    >> "большое" ¶
} _? x > 0 {
    >> "положительное" ¶     // → положительное
} _ {
    >> "отрицательное" ¶
}
```

Здесь два новых символа и третий, который получается из их объединения:

- `?` — это **спросить**: он открывает условие.
- `_` — это **то, что не было указано**: ветка, остающаяся, когда ни один вопрос не совпал.
- `_?` — это оба подряд: *если ничего не совпало, спроси снова*.

Вот почему `_?` пишется именно так. Это не новый символ для изучения — это `_`, за которым следует `?`, и означает ровно то, что означают его две части, прочитанные по порядку.

> Фигурные скобки `{ }` **обязательны** даже для одной инструкции.

## Сопоставление (Match)

```zymbol
балл = 85
оценка = ?? балл {
    90..100 => 'A'
    80..89  => 'B'
    _       => 'F'
}
>> оценка ¶              // → B
```

```zymbol
температура = -5
состояние = ?? температура {
    < 0  => "лёд"
    < 20 => "холодно"
    _    => "жарко"
}
>> состояние ¶              // → лёд
```

Вы уже знаете, что `?` — это «спросить». **`??` — это спросить много раз**: удвоение символа в любом месте языка означает выполнение того, что символ делает один раз, несколько раз. Один `?` проверяет условие; `??` проверяет список вариантов.

Альтернативы объединяются с помощью `||` и могут смешивать типы шаблонов:

```zymbol
клавиша = 'P'
действие = ?? клавиша {
    'p' || 'P' => "пауза"
    < 0 || > 100 => "вне диапазона"
    _ => "игнорировано"
}
>> действие ¶             // → пауза
```

## Циклы

```zymbol
@ i:1..4  { >> i " " }
>> ¶                    // → 1 2 3 4
@ i:1..9:2 { >> i " " }
>> ¶                    // → 1 3 5 7 9
@ i:5..1:1 { >> i " " }
>> ¶                    // → 5 4 3 2 1
```

```zymbol
n = 1
@ n <= 64 { n *= 2 }
>> n ¶                  // → 128
```

```zymbol
фрукты = ["яблоко", "груша", "виноград"]
@ ф:фрукты { >> ф " " }
>> ¶                    // → яблоко груша виноград
@ с:"Привет" { >> с "-" }
>> ¶                    // → П-р-и-в-е-т-
```

```zymbol
@ i:1..10 {
    ? i % 2 == 0 { @> }
    ? i > 7 { @! }
    >> i " "
}
>> ¶                    // → 1 3 5 7
```

```zymbol
счётчик = 0
@:внешний {
    счётчик++
    ? счётчик >= 3 { @:внешний! }
}
>> счётчик ¶             // → 3
```

`@` — это символ **времени**: всё, что повторяется, живёт в нём. Чтобы сократить это время, вы добавляете рядом символ:

- `@!` — `!` — это **сила**: выйти из цикла сейчас.
- `@>` — `>` продвигает вперёд: перейти к следующему витку.
- `@:внешний!` — `:` **связывает имя**, поэтому это прерывает цикл с *именем* внешний, а не ближайший.

Три оператора, и ни один не нужно было запоминать отдельно: это `@` плюс символ, который уже говорит, что он делает.

> **Спецификатор — это количество или условие.** `Целое` — это количество, вычисляется один раз — `@ 0` выполняет тело ноль раз. Всё остальное — условие. Нет истинности: `@ []` и `@ 3.5` отклоняются. Для обхода коллекции используйте `@ x:элементы`; для подсчёта — `@ элементы$#`.

## Функции

```zymbol
сложить(a, b) { <~ a + b }
>> сложить(3, 4) ¶        // → 7
```

```zymbol
факториал(n) {
    ? n <= 1 { <~ 1 }
    <~ n * факториал(n - 1)
}
>> факториал(5) ¶       // → 120
```

Функция читает переменные файла по значению, и запись внутри остаётся внутри:

```zymbol
предел = 100
внутри(n) { <~ n < предел }
>> внутри(42) ¶         // → #1
```

Два символа меняют это, и оба записываются **в сигнатуре и в месте вызова**:

```zymbol
увеличить(счётчик<~) { счётчик = счётчик + 1 }
итог = 0
увеличить(итог<~)
>> итог ¶              // → 1
```

> `p~` — это рабочая копия — тело может переназначить её, и вызывающий остаётся нетронутым.
> `p<~` — это выходной параметр — изменение возвращается обратно. `увеличить(итог)` без символа — семантическая ошибка: аннотация и сигнатура не могут расходиться.

## Лямбды и Замыкания

```zymbol
удвоить = x -> x * 2
сумма = (a, b) -> a + b
>> удвоить(5) ¶          // → 10
>> сумма(3, 7) ¶          // → 10
```

```zymbol
классифицировать = x -> {
    ? x > 0 { <~ "положительное" }
    _? x < 0 { <~ "отрицательное" }
    <~ "ноль"
}
>> классифицировать(-4) ¶         // → отрицательное
```

```zymbol
множитель = 3
утроить = x -> x * множитель
>> утроить(7) ¶          // → 21
```

```zymbol
создать_сумматор(n) { <~ x -> x + n }
сумма10 = создать_сумматор(10)
>> сумма10(5) ¶           // → 15
```

Лямбда может не принимать параметров вообще:

```zymbol
ответ = () -> 42
>> ответ() ¶           // → 42
```

> Лямбда захватывает переменные файла **в момент создания**; именованная функция читает их **в момент вызова**.

## Массивы

```zymbol
arr = [1, 2, 3, 4, 5]
>> arr[1] ¶       // → 1   индексация начинается с 1
>> arr[-1] ¶      // → 5   отрицательное считает с конца
>> arr$# ¶        // → 5   длина
```

```zymbol
arr = [1, 2, 3]
>> (arr$+ 6) ¶          // → [1, 2, 3, 6]   добавить
>> (arr$+[2] 99) ¶      // → [1, 99, 2, 3]  вставить в позицию 2
>> (arr$- 3) ¶          // → [1, 2]         удалить первое вхождение
>> (arr$-[1]) ¶         // → [2, 3]         удалить по индексу 1
>> (arr$[1..2]) ¶       // → [1, 2]         срез, оба конца включены
>> (arr$? 3) ¶          // → #1             содержит
```

Все они начинаются с `$` — символа **коллекции**, и продолжаются символом, указывающим, что в ней делается: `#` сколько, `+` добавить, `-` удалить, `?` спросить, есть ли. И как с `??`, удвоение символа означает выполнение исчерпывающе: `$?` спрашивает *есть ли* значение, `$??` спрашивает *в скольких местах* и возвращает их все.

```zymbol
arr = [3, 1, 2]
>> (arr$^+) ¶     // → [1, 2, 3]   по возрастанию
>> (arr$^-) ¶     // → [3, 2, 1]   по убыванию
```

**Правило результата.** Один оператор, и то, что делает с ним окружающий код, решает: если используется, он **создаёт** и оставляет исходный нетронутым; если отбрасывается, он **изменяет**.

```zymbol
arr = [1, 2, 3]
копия = arr[2]$~ 99
>> arr ¶                // → [1, 2, 3]
>> копия ¶              // → [1, 99, 3]
arr[2]$~ 99
>> arr ¶                // → [1, 99, 3]
```

> **`=` никогда не записывает в коллекцию.** `arr[2] = 99` не является формой Zymbol — `=` присваивает значение **ИМЕНИ**. Изменение части коллекции — это `$~` во всех коллекциях.

`[…]` содержит один тип и проверяется; намеренная смесь **объявляется** с помощью `#[…]`:

```zymbol
смесь = #[1, "два", #1]
>> смесь ¶             // → [1, два, #1]
>> ([1, 2] == #[1, 2]) ¶ // → #1
```

## Многомерная Индексация

`>` спускается по вложенной структуре. Одна группа скобок адресует один элемент, как бы глубоко он ни находился.

```zymbol
m = [[1,2,3], [4,5,6], [7,8,9]]
>> m[2>3] ¶        // → 6   строка 2, столбец 3
>> m[-1>-1] ¶      // → 9   последняя строка, последний столбец
```

```zymbol
m = [[1,2,3], [4,5,6], [7,8,9]]
>> m[1>1 ; 2>2 ; 3>3] ¶          // → [1, 5, 9]          плоская: диагональ
>> m[[1>1, 1>3] ; [3>1, 3>3]] ¶  // → [[1, 3], [7, 9]]   структурированная: углы
```

```zymbol
m = [[1,2,3], [4,5,6]]
>> (m[1>2]$~ 99) ¶      // → [[1, 99, 3], [4, 5, 6]]
```

> `m[1][2]` **не** является формой Zymbol. Цепочный индекс отклоняется как для чтения, так и для записи — одна группа скобок на доступ, а `>` идёт между шагами.

## Словари

Кортеж с именованными полями — это словарь, и с v0.0.9 он записывается как `#(…)`.

```zymbol
человек = #(имя: "Алиса", возраст: 25)
>> человек.имя ¶        // → Алиса
>> человек["возраст"] ¶    // → 25
```

```zymbol
человек = #(имя: "Алиса", возраст: 25)
поле = "имя"
>> человек[поле] ¶     // → Алиса
```

Он изменяемый, ключи можно добавлять, и его можно обходить:

```zymbol
запас = #(груша: 4)
запас["яблоко"]$~ 10
@ к:запас { >> к "=" запас[к] " " }
>> ¶                    // → груша=4 яблоко=10
```

```zymbol
запас = #(груша: 4, яблоко: 10)
@ (к, зн):запас { >> к ":" зн " " }
>> ¶                    // → груша:4 яблоко:10
```

> `#()` — это пустой словарь, чем не мог быть `()` — ему пришлось бы быть также пустым кортежем. Голый `(x: 1)` отклоняется с сообщением: *a dictionary is written `#(…)`* — «словарь записывается как `#(…)`».
> Словарь адресуется по ключу, никогда по позиции, поэтому `человек[1]` — ошибка.

## Кортежи

Кортежи — это **неизменяемые** упорядоченные контейнеры, которые содержат значения разных типов.

```zymbol
точка = (10, 20)
>> точка[1] ¶           // → 10
данные = (42, "Привет", #1, 3.14)
>> данные[3] ¶            // → #1
```

```zymbol
t = (10, 20, 30)
t2 = t[2]$~ 999
>> t ¶                  // → (10, 20, 30)
>> t2 ¶                 // → (10, 999, 30)
```

> Любая попытка изменить кортеж на месте является ошибкой, независимо от оператора — неизменяемость является свойством значения, а не исключением внутри каждого `$`.

## Деструктуризация

```zymbol
arr = [10, 20, 30, 40, 50]
[a, b, c] = arr
>> a " " b " " c ¶      // → 10 20 [30, 40, 50]
```

```zymbol
arr = [10, 20, 30, 40, 50]
[первый, *остаток] = arr
>> первый ¶            // → 10
>> остаток ¶              // → [20, 30, 40, 50]
```

```zymbol
точка = (100, 200)
(px, py) = точка
>> px " " py ¶          // → 100 200
```

```zymbol
человек = #(имя: "Анна", возраст: 25)
#(имя: n, возраст: в) = человек
>> n " " в ¶            // → Анна 25
```

> Форма скобок типизирована: `[…]` принимает массив, `(…)` — кортеж, `#(…)` — словарь. Последнее имя **поглощает остаток**, поэтому деструктуризация никогда не завершается ошибкой по длине — `(a, b, c) = (1,2,3,4,5)` даёт `c = (3,4,5)`, а `##_` когда ничего не остаётся.

## Функции Высшего Порядка

```zymbol
числа = [1, 2, 3, 4, 5]
>> (числа$> (x -> x * 2)) ¶ // → [2, 4, 6, 8, 10]
>> (числа$| (x -> x % 2 == 0)) ¶ // → [2, 4]
>> (числа$< (0, (acc, x) -> acc + x)) ¶ // → 15
```

```zymbol
числа = [1, 2, 3, 4, 5, 6]
удвоить(x) { <~ x * 2 }
большой(x) { <~ x > 3 }
>> (числа$> удвоить) ¶    // → [2, 4, 6, 8, 10, 12]
>> (числа$| большой) ¶    // → [4, 5, 6]
```

```zymbol
база = [#(имя: "Карла", возраст: 28), #(имя: "Анна", возраст: 25)]
по_возрасту = база$^ (a, b -> a.возраст < b.возраст)
>> по_возрасту[1].имя ¶     // → Анна
```

> Именованная функция передаётся в HOF **без скобок**: `числа$> удвоить`. Написание `числа$> (удвоить)` — ошибка синтаксического разбора, потому что `(` открывает лямбду.

## Оператор Pipe

```zymbol
удвоить = x -> x * 2
сложить = (a, b) -> a + b
инк = x -> x + 1
>> (5 |> удвоить(_)) ¶    // → 10
>> (10 |> сложить(_, 5)) ¶  // → 15
>> (5 |> удвоить(_) |> инк(_)) ¶ // → 11
```

## Обработка Ошибок

```zymbol
!? {
    x = 10 / 0
} :! ##Div {
    >> "деление на ноль" ¶  // → деление на ноль
} :! {
    >> "другое: " _err ¶
} :> {
    >> "всегда выполняется" ¶        // → всегда выполняется
}
```

| Тип | Когда |
|------|-------|
| `##Div` | Деление на ноль |
| `##Index` | Индекс вне границ |
| `##Key` | Ключ отсутствует в словаре |
| `##Range` | Вне безопасного диапазона целых |
| `##Type` | Несоответствие типов |
| `##Parse` | Разбор данных |
| `##IO` | Файл / система |
| `##Network` | Сетевые ошибки |
| `##DB` | База данных |
| `##Time` | Дата, которая не существует |
| `##_` | Любая ошибка (всё перехватывает) |

`!` — символ **ошибки и силы**, и читается одинаково в обеих семьях: `$!` спрашивает у значения, является ли оно ошибкой; `$!!` с удвоенным символом распространяет её вверх без вопроса.

> Сбои стандартной библиотеки возвращаются как **мягкие значения ошибок**, которые вы проверяете с помощью `$!` или перехватываете с помощью `!?`, вместо прерывания. `$!!` распространяет одну ошибку вызывающему.

## Модули

```zymbol
# кальк {
    #> { сложить, PI }

    PI := 3.14159
    сложить(a, b) { <~ a + b }
}
```

```zymbol
<# ./кальк => к

>> к::сложить(5, 3) ¶
>> к.PI ¶
```

```zymbol
# моябиб {
    #> { внутр_сложить => сумма }

    внутр_сложить(a, b) { <~ a + b }
}
```

Два символа модуля — это та же идея, теперь применённая к файлам: `#` — это уровень **объявления** — что вещь *есть*, а не её значение — а стрелка указывает, в каком направлении движется код:

```text
<#   стрелка входит: импортировать, принести из другого файла
#>   стрелка выходит: экспортировать, предложить другим файлам
```

Символ направления всегда находится на краю, обращённом в ту сторону, куда указывает. Это та же причина, по которой `<~` возвращается влево (из функции), а `->` входит вправо (в тело лямбды).

> **Модуль объявляет, что он экспортирует.** Блок `#>` обязателен — его пропуск вызывает **E014**, а `#> { }` — это способ модуля сказать, что его поверхность пуста. `::` вызывает функцию, `.` читает константу. В теле модуля могут появляться только импорты, блок экспорта, литеральные инициализаторы и определения функций; всё исполняемое — **E013**.

## Числовые Режимы

Zymbol может записывать числа в **69 системах Unicode-цифр** — деванагари, арабско-индийской, тайской, клингонской pIqaD, математическом жирном шрифте, сегментах LCD и других. Режим является глобальным для процесса и влияет на вывод; арифметика не меняется.

```zymbol
#०९#    // деванагари   (U+0966–U+096F)
#٠٩#    // арабско-индийская (U+0660–U+0669)
#๐๙#    // тайская         (U+0E50–U+0E59)
#09#    // сброс в ASCII
```

```zymbol
x = 42
>> x ¶                  // → 42
#०९#
>> x ¶                  // → ४२
>> 3.14 ¶               // → ३.१४
>> #1 ¶                 // → #१
#09#
```

Цифры из любой поддерживаемой системы письма являются допустимыми литералами в исходном коде:

```zymbol
#०९#
@ i:१..५ { >> i " " }
>> ¶                    // → १ २ ३ ४ ५
#09#
```

Чтение симметрично — цифра понимается в любой системе письма:

```zymbol
>> #|"४२"| ¶            // → 42
>> #|'७'| ¶             // → 7
```

> `#` всегда ASCII, поэтому `#0` остаётся визуально отличимым от цифры ноль в каждой системе письма.
> `#,` и `#^` также записывают свои цифры в активной системе, и разделители следуют за ней — но пара никогда не меняет порядок: `,` группирует, а `.` разделяет в каждой системе письма.

## Операторы Данных

```zymbol
f = ##.42         // в Плавающее
i = ###3.7        // в Целое, округление  → 4
t = ##!3.7        // в Целое, отсечение  → 3
>> f " " i " " t ¶      // → 42 4 3
>> f#? ¶                // → (##., 2, 42)
```

> Плавающее выводится цифрами, никогда в экспоненциальной форме, и отбрасывает завершающий `.0` — `##.42` выводит `42` и всё равно является Плавающим, как показывает `f#?`.

```zymbol
>> #|"42"| ¶       // → 42
>> #|"abc"| ¶      // → abc   отказоустойчиво: возвращает ввод неизменным
>> ##!'A' ¶        // → 65    кодовая точка Символа
```

```zymbol
пи = 3.14159265
>> #.2|пи| ¶       // → 3.14          округлить до 2 десятичных знаков
>> #!2|пи| ¶       // → 3.14          отсечь до 2 десятичных знаков
>> #,|1234567| ¶   // → 1,234,567     разделители тысяч
>> #^|12345.678| ¶ // → 1.2345678e4   научная нотация
```

```zymbol
>> 0x41 ¶        // → A   шестнадцатеричная
>> 0b01000001 ¶  // → A   двоичная
>> 0o101 ¶       // → A   восьмеричная
>> 0d65 ¶        // → A   десятичная
```

> Литерал основания в диапазоне ASCII является **символом**: `0d65 == 'A'` — это `#1`, а `0d65 == 65` — это `#0`. Все четыре основания дают один и тот же символ.

## Как Комбинируются Символы

Вы видели одно и то же на протяжении всего этого руководства: **оператор — это не рисунок для запоминания, это несколько символов подряд, и каждый вносит свой смысл.** Теперь, когда вы знаете их все, вот полный шаблон.

Сначала идёт **в каком мы мире**:

| Символ | Мир | Вы видели его в |
|--------|-----|-----------------|
| `$` | коллекция | `$#` `$+` `$?` `$^-` |
| `@` | время, всё, что повторяется | `@!` `@>` `@~` |
| `#` | что вещь *есть*, а не её значение | `#?` `#(…)` `<#` `#>` |
| `>>` | из программы | `>>` `>>!` `>>?` |
| `<<` | в программу | `<<` `<<\|` `<<\|?` |
| `?` | спросить, без обязательств | `?` `_?` `??` `$?` |
| `!` | сила, или ошибка | `@!` `$!` `!?` |

Затем идёт **что там делается**: `+` добавить, `-` удалить, `^` упорядочить, `~` изменить, `#` посчитать, `|` одна единица, `:` связать имя.

И два правила, которые никогда не подводят:

**Удвоение символа делает его исчерпывающим.** `?` спрашивает один раз, `??` проверяет много случаев. `$?` спрашивает, есть ли значение, `$??` возвращает все места, где оно есть. `!` помечает ошибку, `!!` распространяет её без вопроса.

**Символ режима всегда идёт последним.** Когда `?` или `!` появляются, чтобы сказать *как* что-то делается — неуверенно или принудительно — они являются последним символом оператора: `$??`, `$!!`, `<<|?`, `@!`, `##!`, `>>!`, `>>?`, `@:внешний!`. После них никогда не бывает операции.

Из этого вытекает практическое следствие: **комбинация, которую вы никогда не видели, уже имеет смысл до того, как вы её посмотрите.** Если `$` — это коллекция, `^` — порядок, а `-` — обратный, то `$^-` сортирует по убыванию, и никто не должен был вам говорить.

Не весь инвентарь работает так, и сказать об этом лучше, чем притворяться. Большинство операторов разлагаются чисто. Шесть разлагаются, но означают больше, чем их части: `!?` `:!` `:>` `|>` `::` `$++`. И десять нужно выучить наизусть, потому что они вообще не разлагаются: `¶` `><` `#1` `#0` `0x` `0b` `0o` `0d` `###` `°`.

> Считать непрозрачные символы вместо того, чтобы предполагать, что их мало, — это намеренно: это реальная стоимость запоминания языка. Полный справочник — инвентарь, объявленные омографы и правила, которым должен удовлетворять новый оператор, чтобы существовать, — находится в `SYMBOLS.md` в репозитории интерпретатора.

### v0.0.9 — Коллекции Решили _(сентябрь 2026)_

- **Ломающее** У словаря появилась собственная нотация: `#(ключ: значение)`. Голая форма `(x: 1)` отклоняется, а `#()` — пустой словарь, чем `()` никогда не мог быть
- **Ломающее** Индексированное присваивание изъято: `arr[i] = v` и все составные формы. `=` присваивает значение **ИМЕНИ**; изменение части коллекции — это `$~`
- **Ломающее** Цепочной индекс `m[i][j]` отклоняется как для чтения, так и для записи — `>` идёт между шагами
- **Ломающее** Модуль должен объявлять, что он экспортирует (**E014**); `#> { }` — это способ модуля сказать, что его поверхность пуста
- **Ломающее** Спецификатор цикла — это количество или условие — без истинности. `@ []` и `@ 3.5` отклоняются
- **Добавлено** `##_` — литерал Единицы и способ программы спросить, отсутствует ли что-то
- **Добавлено** `#[…]` — массив, смесь типов элементов которого объявлена
- **Добавлено** `#?` различает четыре коллекции: `##]` `##[` `##)` `##(`
- **Добавлено** `std/time` — часы и гражданский календарь с часовыми поясами и календарной арифметикой
- **Добавлено** `<~>` на верхнем уровне — код выхода программы
- **Добавлено** `@ (k, v):пары` — шаблон в заголовке цикла
- **Добавлено** `#|с|` читает цифру в любой из 69 письменностей; `#,` и `#^` записывают в активной
- **Изменено** `Целое` — безопасное целое, ±(2⁵³ − 1), завершается при ошибке во всех движках
- **Изменено** Именованная функция читает переменные файла во время вызова по значению
- **Изменено** Инструкция, которая только читает имя, выдаёт предупреждение вместо молчаливого пропуска
- **Движки** 660 из 666 файлов корпуса согласны во всех трёх движках, 0 расхождений

### v0.0.8 — Авто-освобождение, `std/term` и Пакеты _(август 2026)_

- **Исправлено** Паритет системы модулей в регистровой VM
