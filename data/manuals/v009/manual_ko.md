# Zymbol-Lang 설명서

> **v0.0.9 기준 개정 — 2026-09-07**

**Zymbol-Lang**은 기호 프로그래밍 언어입니다. 문법에 단어가 없습니다 — 모든 구성이 기호입니다. 어떤 인간 언어에서도 동일하게 작동합니다.

- `if`, `while`, `return` 없음 — 오직 `?`, `@`, `<~`
- 완전한 유니코드 — 어떤 언어나 이모지로도 식별자 사용 가능
- 인간 언어 독립적 — 코드는 어디서나 동일합니다

**인터프리터 버전**: v0.0.9 | **테스트 커버리지**: 660/666 (세 엔진이 일치, 0개 분기)

## 변수와 상수

```zymbol
x = 10              // 변경 가능한 변수
PI := 3.14159       // 상수 — 재할당은 런타임 오류입니다
이름 = "민준"
활성 = #1           // 부울 참
👋 := "안녕하세요"
```

```zymbol
x = 10    // 10
x += 5    // 15
x -= 3    // 12
x *= 2    // 24
x /= 3    // 8
x %= 3    // 2
x ^= 2    // 4
x++       // 5
x--       // 4
```

`°` (도 기호, U+00B0)는 첫 사용 시 변수를 중립 값으로 자동 초기화합니다:

```zymbol
숫자들 = [3, 1, 4, 1, 5]
@ n:숫자들 {
    °합계 += n
}
>> 합계 ¶              // → 14
```

> `°변수` (접두사)는 루프 위에 고정됩니다 — 결과는 `@` 이후에 읽을 수 있습니다.
> `변수°` (접미사)는 루프 안에 고정됩니다 — 루프가 끝나면 사라집니다.

이름만 있는 문장은 변수를 읽고 값을 버리기 때문에 경고합니다:

```zymbol
카운터 = 5
카운터
```

컴파일러는 다음과 같이 경고합니다 (메시지는 항상 영어입니다):

```text
warning: this statement does nothing: '카운터' is read and discarded
  = help: remove it, or use it — `>> name ¶` to print it
```

즉: *«이 문장은 아무것도 하지 않습니다: '카운터'를 읽고 버렸습니다»*.

## 데이터 타입

| 타입 | 리터럴 | `#?` 태그 | 비고 |
|------|--------|-----------|------|
| 정수 | `42`, `-7` | `###` | 안전 정수: ±(2⁵³ − 1) |
| 실수 | `3.14`, `1.5e10` | `##.` | IEEE-754 배정밀도 |
| 문자열 | `"텍스트"` | `##"` | 보간: `"안녕하세요 {이름}"` |
| 문자 | `'A'` | `##'` | 하나의 유니코드 코드 포인트 |
| 부울 | `#1`, `#0` | `##?` | 숫자가 아님 — `#1 ≠ 1` |
| 배열 | `[1, 2, 3]` | `##]` | 단일 타입, 검사됨 |
| 선언된 혼합 | `#[1, "둘"]` | `##[` | `[…]`와 같은 타입, 검사 안 함 |
| 튜플 | `(a, b)` | `##)` | 위치 기반, 불변 |
| 사전 | `#(x: 1, y: 2)` | `##(` | 키 기반, 변경 가능 |
| 함수 | 명명된 함수 참조 | `##()` | 일급; 표시 `<funct/N>` |
| 람다 | `x -> x * 2` | `##->` | 일급; 표시 `<lambd/N>` |
| 단위 | `##_` | `##_` | 부재 — null은 없음 |

```zymbol
>> 42#? ¶               // → (###, 2, 42)
>> [1, 2, 3]#? ¶        // → (##], 3, [1, 2, 3])
>> #(x: 1)#? ¶          // → (##(, 1, #(x: 1))
```

안전 범위를 벗어난 정수는 잡을 수 있는 오류이며, 절대 조용히 감싸지 않습니다:

```zymbol
!? {
    >> (9007199254740991 + 1) ¶
} :! ##Range {
    >> "범위 초과" ¶ // → 범위 초과
}
```

`##_`는 프로그램이 무언가 없는지 묻는 방법입니다:

```zymbol
없음() { }
값 = 없음()
>> (값 == ##_) ¶     // → #1
```

## 출력과 입력

```zymbol
이름 = "민준"
합계 = 3
>> "안녕하세요" ¶             // → 안녕하세요
>> "a=" 이름 " b=" 합계 ¶ // → a=민준 b=3
>> 합계#? ¶            // → (###, 1, 3)
```

```zymbol
<< 이름
<< "이름을 입력하세요: " 이름
<< ###(4) "나이: " 나이
```

**두 기호의 모양을 보세요.** `>>`는 바깥쪽을 가리킵니다: 데이터를 프로그램 밖으로 꺼냅니다. `<<`는 안쪽을 가리킵니다: 데이터를 프로그램 안으로 가져옵니다. 여기서 외울 것은 없습니다 — 화살표는 정보가 어느 방향으로 가는지 보여주며, 같은 아이디어가 무언가를 이동시키는 모든 기호에서 다시 나타납니다.

> `¶`와 `\\`는 동일한 줄바꿈입니다. `>>`는 절대 줄바꿈을 추가하지 않습니다.
> 프롬프트 앞의 타입 지정자는 읽는 동안 검증하고 유효할 때까지 다시 프롬프트합니다:
> `##.` 실수 · `##.(T,D)` 십진수 · `###(N)` 정수 · `##"(N)" 텍스트 · `##'` 한 문자.

파일의 최상위 수준에서 `<~`는 프로그램의 종료 상태입니다:

```zymbol
>> "확인 중" ¶      // → 확인 중
<~ 0
```

## TUI 기본 요소

대화형 프로그램을 위한 터미널 UI 연산자입니다. 대부분 `>>| { }` 블록이 필요합니다 (대체 화면 + 원시 모드).

```zymbol
>>| {
    >>!
    >>~ (1, 1, 0, 10) > "실행 중"
    @~ 1000
    >>~ (2, 1) > "완료."
}
```

```zymbol
>>| {
    [행, 열] = >>?
    >>~ (1, 1) > "터미널: " 행 " x " 열
    <<| 키
    >>~ (2, 1) > "눌림: " 키
}
```

여기서 왜 기호가 곱해지지 않고 결합되는지 알 수 있습니다. `<<`가 입력이고 `?`가 확정 없이 묻는다는 것을 이미 알고 있습니다. 새 기호는 하나뿐입니다:

- `|`는 **단일 단위**이며, 전체 스트림이 아닙니다.

이렇게 하면 두 키보드 연산자가 스스로 읽힙니다:

```text
<<        |             ?
입력      단일 단위    확정 없이

<<|   키 하나를 받고, 하나가 있을 때까지 기다립니다
<<|?  키가 있는지 확인하고, 없으면 계속 진행합니다
```

반대편도 마찬가지입니다: `>>`는 보내고, `>>!`는 **강제로** 보내며(전체 화면을 지웁니다), `>>?`는 쓰는 대신 **묻습니다**(터미널이 얼마나 큰지). 오른쪽의 기호가 모드를 바꾸는 기호이며, 항상 마지막에 옵니다.

> `>>!`는 화면을 지웁니다. `>>?`는 `[행, 열]`을 반환합니다. `@~ N`은 N밀리초 동안 잠자기합니다.
> `<<|`는 키 누름을 읽습니다(차단). `<<|?`는 차단하지 않고 폴링합니다(없으면 `'\0'`).
> 화살표 키는 `'↑' '↓' '←' '→'`로 디코딩됩니다. ESC는 코드 포인트 27입니다.
> 위치 지정 출력 튜플: `(행, 열, BKS, 전경, 배경)` — 모든 슬롯은 쉼표로 생략할 수 있습니다 (`>>~ (,,, 196) > "빨강"`).
> BKS 비트마스크: `1`=굵게, `2`=기울임, `4`=밑줄. ANSI 256색 팔레트 (`0`=터미널 기본값).

## 연산자

```zymbol
a = 10
b = 3
결과1 = a + b    // 13
결과2 = a - b    // 7
결과3 = a * b    // 30
결과4 = a / b    // 3  (정수 나눗셈)
결과5 = a % b    // 1
결과6 = a ^ b    // 1000
```

```zymbol
a = 10
b = 3
비교1 = a == b    // #0
비교2 = a <> b    // #1
비교3 = a < b     // #0
비교4 = a >= b    // #1
논리1 = #1 && #0  // #0
논리2 = !#1       // #0
```

> `==`는 절대 강제 변환하지 않습니다: `"5" == 5`는 `#0`입니다. 순서는 강제합니다: `"5" > 4`는 `#1`이고, `"४२" > 5`도 마찬가지입니다 — 69개 문자 체계 중 어느 것이든 숫자 텍스트는 숫자로 비교됩니다.
> 함수는 오직 자기 자신과만 같으며, 같은 본문을 가진 다른 함수와는 절대 같지 않습니다.

## 문자열

```zymbol
이름 = "민준"
n = 42
>> "안녕하세요 " 이름 " 당신은 " n " 을 가지고 있습니다" ¶ // → 안녕하세요 민준 당신은 42 을 가지고 있습니다
설명 = "안녕하세요 {이름}, 당신은 {n} 을 가지고 있습니다"
>> 설명 ¶              // → 안녕하세요 민준, 당신은 42 을 가지고 있습니다
```

```zymbol
s = "안녕하세요 세계"
길이 = s$#                  // 8
부분 = s$[1..3]             // "안녕하"
포함 = s$? "세계"          // #1
조각 = "a,b,c,d"$/ ','    // [a, b, c, d]
교체 = s$~~["세":"네"]        // "안녕하네요 네계"
선 = "─" $* 20
```

> `+`는 숫자에만 사용됩니다. 문자열에는 인접 배치나 보간을 사용하세요.
> `\{`와 `\}`는 리터럴 중괄호입니다 — 이스케이프는 대칭적입니다.

## 제어 흐름

```zymbol
x = 7
? x > 100 {
    >> "큰" ¶
} _? x > 0 {
    >> "양수" ¶     // → 양수
} _ {
    >> "음수" ¶
}
```

여기에 두 개의 새 기호가 있고, 세 번째는 그것들을 함께 놓은 것입니다:

- `?`는 **묻기**입니다: 조건을 엽니다.
- `_`는 **지정되지 않은 것**입니다: 어떤 질문도 일치하지 않을 때 남는 분기입니다.
- `_?`는 둘이 연달아: *아무것도 일치하지 않으면 다시 물어라*.

이것이 `_?`가 이렇게 쓰이는 이유입니다. 배울 새 기호가 아닙니다 — `_` 뒤에 `?`가 오는 것이며, 두 부분이 순서대로 읽힐 때 의미하는 것을 정확히 의미합니다.

> 중괄호 `{ }`는 단일 문장에도 **필수**입니다.

## 일치

```zymbol
점수 = 85
등급 = ?? 점수 {
    90..100 => 'A'
    80..89  => 'B'
    _       => 'F'
}
>> 등급 ¶              // → B
```

```zymbol
온도 = -5
상태 = ?? 온도 {
    < 0  => "얼음"
    < 20 => "차가움"
    _    => "뜨거움"
}
>> 상태 ¶              // → 얼음
```

`?`가 "묻기"라는 것을 이미 알고 있습니다. **`??`는 여러 번 묻기**입니다: 언어 어디서든 기호를 두 배로 하는 것은 그 기호가 한 번 하는 일을 여러 번 하는 것입니다. 하나의 `?`는 조건을 시험합니다; `??`는 케이스 목록에 대해 시험합니다.

대안은 `||`로 결합되며 패턴 종류를 혼합할 수 있습니다:

```zymbol
키 = 'P'
동작 = ?? 키 {
    'p' || 'P' => "일시정지"
    < 0 || > 100 => "범위 초과"
    _ => "무시됨"
}
>> 동작 ¶             // → 일시정지
```

## 루프

```zymbol
@ i:1..4  { >> i " " }
>> ¶                    // → 1 2 3 4
@ i:1..9:2 { >> i " " }
>> ¶                    // → 1 3 5 7 9
@ i:5..1:1 { >> i " " }
>> ¶                    // → 5 4 3 2 1
```

```zymbol
n = 1
@ n <= 64 { n *= 2 }
>> n ¶                  // → 128
```

```zymbol
과일 = ["사과", "배", "포도"]
@ f:과일 { >> f " " }
>> ¶                    // → 사과 배 포도
@ c:"안녕하세요" { >> c "-" }
>> ¶                    // → 안-녕-하-세-요-
```

```zymbol
@ i:1..10 {
    ? i % 2 == 0 { @> }
    ? i > 7 { @! }
    >> i " "
}
>> ¶                    // → 1 3 5 7
```

```zymbol
카운터 = 0
@:외부 {
    카운터++
    ? 카운터 >= 3 { @:외부! }
}
>> 카운터 ¶             // → 3
```

`@`는 **시간**의 기호입니다: 반복되는 모든 것은 그 안에 살아 있습니다. 그 시간을 자르려면 옆에 기호를 추가합니다:

- `@!` — `!`는 **강제**입니다: 지금 루프를 떠나세요.
- `@>` — `>`는 앞으로 밀어냅니다: 다음 회차로 이동합니다.
- `@:외부!` — `:`는 **이름을 묶습니다**, 따라서 이것은 *외부*라는 이름의 루프를 자르고, 가장 가까운 것을 자르는 것이 아닙니다.

세 연산자이며, 어느 것도 따로 외울 필요가 없었습니다: `@` 더하기 그것이 하는 일을 이미 말하는 기호입니다.

> **지정자는 개수 또는 조건입니다.** `정수`는 개수이며, 한 번 평가됩니다 — `@ 0`은 본문을 0번 실행합니다. 다른 모든 것은 조건입니다. 진리값은 없습니다: `@ []`와 `@ 3.5`는 거부됩니다. 컬렉션을 순회하려면 `@ x:항목`을 사용하세요; 개수를 세려면 `@ 항목$#`.

## 함수

```zymbol
더하기(a, b) { <~ a + b }
>> 더하기(3, 4) ¶        // → 7
```

```zymbol
계승(n) {
    ? n <= 1 { <~ 1 }
    <~ n * 계승(n - 1)
}
>> 계승(5) ¶       // → 120
```

함수는 파일의 변수를 값으로 읽고, 내부의 쓰기는 내부에 머무릅니다:

```zymbol
한계 = 100
내부(n) { <~ n < 한계 }
>> 내부(42) ¶         // → #1
```

두 기호가 그것을 바꾸며, 둘 다 **서명과 호출 지점에** 쓰입니다:

```zymbol
증가(카운터<~) { 카운터 = 카운터 + 1 }
합계 = 0
증가(합계<~)
>> 합계 ¶              // → 1
```

> `p~`는 작업 복사본입니다 — 본문이 그것을 재할당할 수 있고 호출자는 영향을 받지 않습니다.
> `p<~`는 출력 매개변수입니다 — 변경이 돌아옵니다. 기호 없이 `증가(합계)`는 의미 오류입니다: 주석과 서명은 분리될 수 없습니다.

## 람다와 클로저

```zymbol
두배 = x -> x * 2
합 = (a, b) -> a + b
>> 두배(5) ¶          // → 10
>> 합(3, 7) ¶          // → 10
```

```zymbol
분류 = x -> {
    ? x > 0 { <~ "양수" }
    _? x < 0 { <~ "음수" }
    <~ "영"
}
>> 분류(-4) ¶         // → 음수
```

```zymbol
인수 = 3
세배 = x -> x * 인수
>> 세배(7) ¶          // → 21
```

```zymbol
덧셈기_생성(n) { <~ x -> x + n }
더하기10 = 덧셈기_생성(10)
>> 더하기10(5) ¶           // → 15
```

람다는 매개변수를 전혀 받지 않을 수 있습니다:

```zymbol
답 = () -> 42
```

## 배열

```zymbol
배열 = [1, 2, 3, 4, 5]
>> 배열[1] ¶       // → 1   인덱싱은 1부터 시작합니다
>> 배열[-1] ¶      // → 5   음수는 끝에서부터 셉니다
>> 배열$# ¶        // → 5   길이
```

```zymbol
배열 = [1, 2, 3]
>> (배열$+ 6) ¶          // → [1, 2, 3, 6]   추가
>> (배열$+[2] 99) ¶      // → [1, 99, 2, 3]  위치 2에 삽입
>> (배열$- 3) ¶          // → [1, 2]         첫 번째 항목 제거
>> (배열$-[1]) ¶         // → [2, 3]         인덱스 1에서 제거
>> (배열$[1..2]) ¶       // → [1, 2]         슬라이스, 양 끝 포함
>> (배열$? 3) ¶          // → #1             포함
```

모두 `$`로 시작합니다. 이것은 **컬렉션**의 기호이며, 그 안에서 무엇이 행해지는지 말하는 기호로 이어집니다: `#` 몇 개, `+` 추가, `-` 제거, `?` 있는지 묻기. 그리고 `??`처럼 기호를 두 배로 하는 것은 그것을 철저히 하는 것을 의미합니다: `$?`는 값이 *있는지* 묻고, `$??`는 *몇 군데에* 있는지 묻고 모두 반환합니다.

```zymbol
배열 = [3, 1, 2]
>> (배열$^+) ¶     // → [1, 2, 3]   오름차순
>> (배열$^-) ¶     // → [3, 2, 1]   내림차순
```

**결과의 규칙.** 하나의 연산자, 그리고 주변 코드가 그것으로 무엇을 하는지가 결정합니다: 사용되면 **생성**하고 원본을 그대로 둡니다; 버려지면 **수정**합니다.

```zymbol
배열 = [1, 2, 3]
복사 = 배열[2]$~ 99
>> 배열 ¶                // → [1, 2, 3]
>> 복사 ¶              // → [1, 99, 3]
배열[2]$~ 99
>> 배열 ¶                // → [1, 99, 3]
```

> **`=`는 절대 컬렉션에 쓰지 않습니다.** `배열[2] = 99`는 Zymbol의 형태가 아닙니다 — `=`는 **이름**에 값을 줍니다. 컬렉션의 일부를 변경하는 것은 `$~`이며, 모든 컬렉션에서 그러합니다.

`[…]`는 단일 타입을 담고 검사됩니다; 의도적 혼합은 `#[…]`로 **선언**됩니다:

```zymbol
혼합 = #[1, "둘", #1]
>> 혼합 ¶             // → [1, 둘, #1]
>> ([1, 2] == #[1, 2]) ¶ // → #1
```

## 다차원 인덱싱

`>`는 중첩 구조로 내려갑니다. 하나의 대괄호 그룹이 하나의 요소를 지시하며, 얼마나 깊든 상관없습니다.

```zymbol
m = [[1,2,3], [4,5,6], [7,8,9]]
>> m[2>3] ¶        // → 6   행 2, 열 3
>> m[-1>-1] ¶      // → 9   마지막 행, 마지막 열
```

```zymbol
m = [[1,2,3], [4,5,6], [7,8,9]]
>> m[1>1 ; 2>2 ; 3>3] ¶          // → [1, 5, 9]          평면: 대각선
>> m[[1>1, 1>3] ; [3>1, 3>3]] ¶  // → [[1, 3], [7, 9]]   구조화: 모서리
```

```zymbol
m = [[1,2,3], [4,5,6]]
>> (m[1>2]$~ 99) ¶      // → [[1, 99, 3], [4, 5, 6]]
```

> `m[1][2]`는 Zymbol의 형태가 **아닙니다**. 연쇄 인덱스는 읽기와 쓰기 모두에서 거부됩니다 — 접근마다 하나의 대괄호 그룹, 그리고 `>`가 단계 사이에 들어갑니다.

## 사전

이름 있는 필드를 가진 튜플은 사전이며, v0.0.9부터 `#(…)`로 작성됩니다.

```zymbol
사람 = #(이름: "민준", 나이: 25)
>> 사람.이름 ¶        // → 민준
>> 사람["나이"] ¶    // → 25
```

```zymbol
사람 = #(이름: "민준", 나이: 25)
필드 = "이름"
>> 사람[필드] ¶     // → 민준
```

변경 가능하며, 키를 추가할 수 있고 순회할 수 있습니다:

```zymbol
재고 = #(배: 4)
재고["사과"]$~ 10
@ k:재고 { >> k "=" 재고[k] " " }
>> ¶                    // → 배=4 사과=10
```

```zymbol
재고 = #(배: 4, 사과: 10)
@ (k, v):재고 { >> k ":" v " " }
>> ¶                    // → 배:4 사과:10
```

> `#()`는 빈 사전이며, `()`는 그럴 수 없었습니다 — 빈 튜플이기도 해야 했으니까요. 벗은 `(x: 1)`는 이 메시지와 함께 거부됩니다: *a dictionary is written `#(…)`* — «사전은 `#(…)`로 씁니다».
> 사전은 키로 지시되며, 위치로는 결코 아닙니다. 따라서 `사람[1]`은 오류입니다.

## 튜플

튜플은 **불변** 순서 컨테이너이며, 서로 다른 타입의 값을 담을 수 있습니다.

```zymbol
점 = (10, 20)
>> 점[1] ¶           // → 10
데이터 = (42, "안녕하세요", #1, 3.14)
>> 데이터[3] ¶            // → #1
```

```zymbol
t = (10, 20, 30)
t2 = t[2]$~ 999
>> t ¶                  // → (10, 20, 30)
>> t2 ¶                 // → (10, 999, 30)
```

> 튜플을 제자리에서 수정하려는 시도는 연산자가 무엇이든 오류입니다 — 불변성은 값의 속성이며, 각 `$` 내부의 예외가 아닙니다.

## 구조 분해

```zymbol
배열 = [10, 20, 30, 40, 50]
[a, b, c] = 배열
>> a " " b " " c ¶      // → 10 20 [30, 40, 50]
```

```zymbol
배열 = [10, 20, 30, 40, 50]
[첫째, *나머지] = 배열
>> 첫째 ¶            // → 10
>> 나머지 ¶              // → [20, 30, 40, 50]
```

```zymbol
점 = (100, 200)
(px, py) = 점
>> px " " py ¶          // → 100 200
```

```zymbol
사람 = #(이름: "지우", 나이: 25)
#(이름: n, 나이: a) = 사람
>> n " " a ¶            // → 지우 25
```

> 괄호 모양은 타입이 지정됩니다: `[…]`는 배열, `(…)`는 튜플, `#(…)`는 사전을 받습니다. 마지막 이름은 **나머지를 흡수**하므로 구조 분해는 길이로 실패하지 않습니다 — `(a, b, c) = (1,2,3,4,5)`는 `c = (3,4,5)`를 주고, 아무것도 남지 않으면 `##_`입니다.

## 고차 함수

```zymbol
숫자들 = [1, 2, 3, 4, 5]
>> (숫자들$> (x -> x * 2)) ¶ // → [2, 4, 6, 8, 10]
>> (숫자들$| (x -> x % 2 == 0)) ¶ // → [2, 4]
>> (숫자들$< (0, (누적, x) -> 누적 + x)) ¶ // → 15
```

```zymbol
숫자들 = [1, 2, 3, 4, 5, 6]
두배(x) { <~ x * 2 }
큰(x) { <~ x > 3 }
>> (숫자들$> 두배) ¶    // → [2, 4, 6, 8, 10, 12]
>> (숫자들$| 큰) ¶    // → [4, 5, 6]
```

```zymbol
기준 = [#(이름: "카를라", 나이: 28), #(이름: "지우", 나이: 25)]
나이순 = 기준$^ (a, b -> a.나이 < b.나이)
>> 나이순[1].이름 ¶     // → 지우
```

> 명명된 함수는 HOF에 **괄호 없이** 갑니다: `숫자들$> 두배`. `숫자들$> (두배)`라고 쓰는 것은 파싱 오류입니다, 왜냐하면 `(`는 람다를 열기 때문입니다.

```zymbol
두배 = x -> x * 2
```

## 오류 처리

```zymbol
!? {
    x = 10 / 0
} :! ##Div {
    >> "0으로 나눔" ¶  // → 0으로 나눔
} :! {
    >> "기타: " _err ¶
} :> {
    >> "항상 실행" ¶        // → 항상 실행
}
```

| 종류 | 언제 |
|------|------|
| `##Div` | 0으로 나눔 |
| `##Index` | 인덱스 범위 초과 |
| `##Key` | 사전에 키 없음 |
| `##Range` | 안전 정수 범위 초과 |
| `##Type` | 타입 불일치 |
| `##Parse` | 데이터 파싱 |
| `##IO` | 파일 / 시스템 |
| `##Network` | 네트워크 오류 |
| `##DB` | 데이터베이스 |
| `##Time` | 존재하지 않는 날짜 |
| `##_` | 모든 오류 (전부 잡음) |

`!`는 **오류와 강제**의 기호이며, 두 계열에서 같은 방식으로 읽힙니다: `$!`는 값이 오류인지 묻고; `$!!`는 기호가 두 배가 되어 묻지 않고 위로 전파합니다.

> 표준 라이브러리 실패는 중단하는 대신 `$!`로 검사하거나 `!?`로 잡는 **부드러운 오류 값**으로 반환됩니다. `$!!`는 하나를 호출자에게 전파합니다.

## 모듈

```zymbol
# 계산기 {
    #> { 더하기, PI }

    PI := 3.14159
    더하기(a, b) { <~ a + b }
}
```

```zymbol
<# ./계산기 => c

>> c::더하기(5, 3) ¶
>> c.PI ¶
```

```zymbol
# 내_라이브러리 {
    #> { 내부_더하기 => 합 }

    내부_더하기(a, b) { <~ a + b }
}
```

두 모듈 기호는 같은 아이디어이며, 이제 파일에 적용됩니다: `#`는 **선언**의 수준입니다 — 어떤 것이 *무엇인지*, 그 값이 아니라 — 그리고 화살표는 코드가 어느 방향으로 가는지 말합니다:

```text
<#   화살표가 들어옴: 가져오기, 다른 파일에서 가져옴
#>   화살표가 나감: 내보내기, 다른 파일에 제공
```

방향 기호는 항상 가리키는 방향을 향한 가장자리에 앉습니다. `<~`가 왼쪽으로 돌아오고(함수 밖으로) `->`가 오른쪽으로 들어가는(람다의 본문으로) 같은 이유입니다.

> **모듈은 내보내는 것을 선언합니다.** `#>` 블록은 필수입니다 — 생략하면 **E014**이며, `#> { }`는 모듈이 그 표면이 비어 있다고 말하는 방법입니다. `::`는 함수를 호출하고, `.`는 상수를 읽습니다. 모듈 본문에는 가져오기, 내보내기 블록, 리터럴 초기화, 함수 정의만 나타날 수 있습니다; 실행 가능한 것은 무엇이든 **E013**입니다.

## 표준 라이브러리

네이티브 모듈은 다른 모듈처럼 가져옵니다:

| 모듈 | 함수 |
|------|------|
| `std/math` | `sqrt exp ln log pow abs ceil floor round min max sin cos tan asin acos atan atan2 sinh cosh tanh sigmoid` · `PI` `E` |
| `std/random` | `entero rango peso_f64` |
| `std/json` | `decode decode_map encode` |
| `std/io` | `read write append exists delete list mkdir` |
| `std/net` | `get post post_json head` |
| `std/db` | `connect exec query query_one tx commit rollback` … |
| `std/term` | `width pad_left pad_right center truncate` |
| `std/time` | `now today parts of format add diff` |

```zymbol
<# std/math => m

>> m::sqrt(16.0) ¶      // → 4
>> m.PI ¶               // → 3.141592653589793
```

```zymbol
<# std/term => t

>> t::width("手番") ¶            // → 4   두 글자, 네 열
>> "|" t::center("go", 8) "|" ¶ // → |   go   |
```

```zymbol
<# std/time => T

날 = T::of(2026, 1, 31)
>> T::format(날, "%Y-%m-%d") ¶ // → 2026-01-31
>> T::format(T::add(날, 1, "month"), "%Y-%m-%d") ¶ // → 2026-02-28
```

> `std/term`은 **표시 열**을 측정하며, 문자를 측정하지 않습니다: CJK와 대부분의 이모지는 2열이므로 `t::width`로 표를 배치하세요, 절대 `$#`가 아닙니다.
> `std/time`에서 순간은 에포크 이후 밀리초입니다. 하루 미만은 기간, 하루부터는 달력입니다 — 따라서 한 달은 같은 날짜에 떨어지며, 클램프됩니다. `차이(a, b)`는 `a - b`이므로 더 이른 순간을 먼저 주면 음수 답이 나옵니다.

## 패키지

`.zyp`는 다중 파일 프로그램을 하나의 이식 가능한 파일로 묶습니다. **소스**의 아카이브이며 바이너리가 아니므로, `zymbol` 바이너리가 실행되는 곳이면 어디서든 실행됩니다.

```bash
zymbol package 내_프로젝트/ --script main.zy -o 내_프로젝트.zyp
zymbol run 내_프로젝트.zyp
```

> 아카이브는 진입 스크립트와 필요한 엔진 버전을 선언하는 매니페스트(`zyp.toml`)를 담고 있습니다. `zymbol run`은 그것을 임시 디렉토리로 풀고 거기서 실행하므로, 코드는 일회용이며 스크립트가 쓰는 것은 실제 작업 디렉토리에 떨어집니다. 플레이그라운드도 `.zyp` 파일을 로드합니다.

## 숫자 모드

Zymbol은 숫자를 **69개의 유니코드 숫자 문자 체계**로 쓸 수 있습니다 — 데바나가리, 아랍-인도, 태국, 클링온 pIqaD, 수학 굵게, LCD 세그먼트 등. 모드는 프로세스 전역이며 출력에 영향을 줍니다; 산술은 변경되지 않습니다.

```zymbol
#०९#    // 데바나가리   (U+0966–U+096F)
#٠٩#    // 아랍-인도 (U+0660–U+0669)
#๐๙#    // 태국         (U+0E50–U+0E59)
#09#    // ASCII로 재설정
```

```zymbol
x = 42
>> x ¶                  // → 42
#०९#
>> x ¶                  // → ४२
>> 3.14 ¶               // → ३.१४
>> #1 ¶                 // → #१
#09#
```

지원되는 모든 문자 체계의 숫자는 소스에서 유효한 리터럴입니다:

```zymbol
#०९#
@ i:१..५ { >> i " " }
>> ¶                    // → १ २ ३ ४ ५
#09#
```

읽기도 대칭적입니다 — 숫자는 어떤 문자 체계에서든 이해됩니다:

```zymbol
>> #|"४२"| ¶            // → 42
>> #|'७'| ¶             // → 7
```

> `#`는 항상 ASCII이므로, `#0`은 모든 문자 체계에서 숫자 0과 시각적으로 구별됩니다.
> `#,`와 `#^`도 활성 문자 체계로 숫자를 쓰며, 구분자도 그것을 따릅니다 — 그러나 쌍은 절대 뒤집히지 않습니다: `,`는 묶고 `.`는 나눕니다, 모든 문자 체계에서.

## 데이터 연산자

```zymbol
f = ##.42         // 실수로
i = ###3.7        // 정수로, 반올림  → 4
t = ##!3.7        // 정수로, 잘라냄  → 3
>> f " " i " " t ¶      // → 42 4 3
>> f#? ¶                // → (##., 2, 42)
```

> 실수는 숫자로 인쇄되며, 절대 지수로 인쇄되지 않고, 끝의 `.0`을 버립니다 — `##.42`는 `42`를 쓰며 여전히 실수입니다, `f#?`가 보여주듯이.

```zymbol
>> #|"42"| ¶       // → 42
>> #|"abc"| ¶      // → abc   실패 안전: 입력을 변경하지 않고 반환
>> ##!'A' ¶        // → 65    문자의 코드 포인트
```

```zymbol
pi = 3.14159265
>> #.2|pi| ¶       // → 3.14          소수점 2자리로 반올림
>> #!2|pi| ¶       // → 3.14          소수점 2자리로 잘라냄
>> #,|1234567| ¶   // → 1,234,567     천 단위 구분
>> #^|12345.678| ¶ // → 1.2345678e4   과학적 표기법
```

```zymbol
>> 0x41 ¶        // → A   16진수
>> 0b01000001 ¶  // → A   2진수
>> 0o101 ¶       // → A   8진수
>> 0d65 ¶        // → A   10진수
```

> ASCII 범위의 진법 리터럴은 **문자**입니다: `0d65 == 'A'`는 `#1`이고, `0d65 == 65`는 `#0`입니다. 네 진법 모두 같은 문자를 표기합니다.

## 완전한 예제: FizzBuzz

```zymbol
분류(숫자) {
    ? 숫자 % 15 == 0 { <~ "FizzBuzz" }
    _? 숫자 % 3  == 0 { <~ "Fizz" }
    _? 숫자 % 5  == 0 { <~ "Buzz" }
    <~ 숫자
}

@ i:1..20 { >> 분류(i) ¶ }
// → 1 · 2 · Fizz · 4 · Buzz · Fizz · 7 · 8 · Fizz · Buzz · 11 · Fizz · 13 · 14 ·
//   FizzBuzz · 16 · 17 · Fizz · 19 · Buzz   (한 줄에 하나)
```

## 기호가 결합되는 방식

이 설명서 전체에서 같은 것을 보았습니다: **연산자는 외울 그림이 아니라 한 줄에 여러 기호이며, 각각이 자기 의미를 기여합니다.** 이제 그것들을 모두 알았으니, 전체 패턴입니다.

먼저 **우리가 어떤 세계에 있는지**가 옵니다:

| 기호 | 세계 | 어디서 보았는가 |
|------|------|----------------|
| `$` | 컬렉션 | `$#` `$+` `$?` `$^-` |
| `@` | 시간, 반복되는 모든 것 | `@!` `@>` `@~` |
| `#` | 어떤 것이 *무엇인지*, 그 값이 아니라 | `#?` `#(…)` `<#` `#>` |
| `>>` | 프로그램 밖으로 | `>>` `>>!` `>>?` |
| `<<` | 프로그램 안으로 | `<<` `<<\|` `<<\|?` |
| `?` | 묻기, 확정 없이 | `?` `_?` `??` `$?` |
| `!` | 강제, 또는 오류 | `@!` `$!` `!?` |

다음으로 **거기서 무엇이 행해지는지**가 옵니다: `+` 추가, `-` 제거, `^` 순서, `~` 수정, `#` 세기, `|` 단일 단위, `:` 이름 묶기.

그리고 절대 실패하지 않는 두 가지 규칙:

**기호를 두 배로 하면 철저해집니다.** `?`는 한 번 묻고, `??`는 여러 케이스를 시험합니다. `$?`는 값이 있는지 묻고, `$??`는 있는 모든 곳을 반환합니다. `!`는 오류를 표시하고, `!!`는 묻지 않고 전파합니다.

**모드 기호는 항상 마지막에 옵니다.** `?`나 `!`가 무언가가 *어떻게* 행해지는지 — 주저하며 또는 강제로 — 말하기 위해 나타날 때, 그것들은 연산자의 마지막 기호입니다: `$??`, `$!!`, `<<|?`, `@!`, `##!`, `>>!`, `>>?`, `@:외부!`. 그것들 뒤에는 절대 연산이 없습니다.

거기서 실용적인 것이 나옵니다: **본 적 없는 조합도, 찾아보기 전에 이미 의미가 통합니다.** `$`가 컬렉션이고 `^`가 순서이고 `-`가 반대라면, `$^-`는 내림차순으로 정렬하며, 아무도 당신에게 말해줄 필요가 없었습니다.

전체 목록이 이렇게 작동하지는 않으며, 그렇게 말하는 것이 가장하는 것보다 낫습니다. 대부분의 연산자는 깔끔하게 분해됩니다. 여섯 개는 분해되지만 부분보다 더 많은 것을 의미합니다: `!?` `:!` `:>` `|>` `::` `$++`. 그리고 열 개는 전혀 분해되지 않아 외워야 합니다: `¶` `><` `#1` `#0` `0x` `0b` `0o` `0d` `###` `°`.

> 불투명한 것을 적다고 가정하는 대신 세는 것은 의도적입니다: 그것들은 언어의 실제 암기 비용입니다. 완전한 참조 — 목록, 선언된 동형이의어, 새 연산자가 존재하기 위해 충족해야 하는 규칙 — 는 인터프리터 저장소의 `SYMBOLS.md`에 있습니다.

## 기호 참조

| 기호 | 연산 | 기호 | 연산 |
|------|------|------|------|
| `=` | 변수 | `$#` | 길이 |
| `:=` | 상수 | `$+` | 추가 |
| `>>` | 출력 | `$+[i]` | 인덱스에 삽입 (1부터) |
| `<<` | 입력 | `$-` | 값으로 첫 번째 제거 |
| `¶` / `\\` | 줄바꿈 | `$--` | 값으로 모두 제거 |
| `?` | 만약 | `$-[i]` | 인덱스에서 제거 (1부터) |
| `_?` | 그렇지 않으면 | `$-[i..j]` | 범위 제거 (1부터) |
| `_` | 그렇지 않으면 / 와일드카드 | `$?` | 포함 |
| `??` | 일치 | `$??` | 모든 인덱스 찾기 (1부터) |
| `\|\|` | 일치 분기에서 또는-패턴 | `$[s..e]` | 슬라이스 (1부터) |
| `@` | 루프 | `$>` | 매핑 |
| `@ N { }` | N번 루프 | `$\|` | 필터 |
| `@!` | 중단 | `$<` | 축소 |
| `@>` | 계속 | `$/ 구분자` | 문자열 분할 |
| `@:이름 { }` | 이름표 루프 | `$++ a b c` | 이어 붙여 구축 |
| `@:이름!` | 이름표 중단 | `$~~[p:r]` | 문자열 교체 |
| `@:이름>` | 이름표 계속 | `$*` | 문자열 반복 |
| `->` | 람다 | `배열[i]$~ v` | 유일한 업데이트 형식 |
| `<~` | 반환 / 출력 매개변수 | `~` | 작업 복사본 매개변수 |
| `배열[i>j]` | 탐색 인덱스 | `배열[p ; q]` | 평면 추출 |
| `$^+` | 오름차순 정렬 | `$^-` | 내림차순 정렬 |
| `$^` | 비교자로 정렬 | `\|>` | 파이프 |
| `!?` | 시도 | `:!` | 잡기 |
| `:>` | 마지막으로 | `$!` | 오류인가 |
| `$!!` | 오류 전파 | `#1` / `#0` | 참 / 거짓 |
| `##_` | 단위 — 부재 | `[…]` | 배열, 단일 타입 |
| `#[…]` | 배열, 선언된 혼합 | `#(…)` | 사전 |
| `(…)` | 위치 튜플 | `#()` | 빈 사전 |
| `<#` | 가져오기 | `#>` | 내보내기 |
| `#` | 모듈 선언 | `::` | 모듈 호출 |
| `.` | 필드 / 상수 접근 | `#?` | 타입 메타데이터 |
| `#\|..\|` | 숫자 파싱 | `##.` | 실수로 변환 |
| `###` | 정수로 변환 (반올림) | `##!` | 정수로 변환 (잘라냄) |
| `#.N\|..\|` | 반올림 | `#!N\|..\|` | 잘라냄 |
| `#,\|..\|` | 천 단위 구분 | `#^\|..\|` | 과학적 |
| `#d0d9#` | 숫자 모드 전환 | `#09#` | ASCII로 재설정 |
| `<\ ..\>` | 셸 실행 | `><` | CLI 인수 |
| `\ var` | 변수 파괴 | `°x` / `x°` | 뜨거운 정의 |
| `>>\|` | TUI 블록 (대체 화면) | `>>~` | 위치 지정 출력 |
| `>>!` | 화면 지움 | `>>?` | 터미널 크기 질의 |
| `<<\|` | 차단 키 누름 | `<<\|?` | 비차단 키 누름 |
| `@~ N` | N밀리초 잠자기 | `0d` `0x` `0o` `0b` | 진법 리터럴 |

## 릴리스 변경 기록

### v0.0.9 — 컬렉션이 결정하다 _(2026년 9월)_

- **파괴적** 사전이 자체 표기법을 가집니다: `#(키: 값)`. 벗은 `(x: 1)`는 거부되며, `#()`는 빈 사전입니다 — `()`가 결코 될 수 없었던 것
- **파괴적** 인덱스 할당이 철회되었습니다: `배열[i] = v`와 모든 복합 형식. `=`는 **이름**에 값을 줍니다; 컬렉션의 일부를 변경하는 것은 `$~`
- **파괴적** 연쇄 인덱스 `m[i][j]`는 읽기와 쓰기 모두에서 거부됩니다 — `>`가 단계 사이에 들어갑니다
- **파괴적** 모듈은 내보내는 것을 선언해야 합니다 (**E014**); `#> { }`는 모듈이 표면이 비어 있다고 말하는 방법입니다
- **파괴적** 루프 지정자는 개수 또는 조건입니다 — 진리값은 없습니다. `@ []`와 `@ 3.5`는 거부됩니다
- **추가** `##_` — 단위 리터럴, 그리고 프로그램이 무언가 없는지 묻는 방법
- **추가** `#[…]` — 요소 타입의 혼합이 선언된 배열
- **추가** `#?`가 네 컬렉션을 구분합니다: `##]` `##[` `##)` `##(`
- **추가** `std/time` — 시계와 시민 달력, 시간대와 달력 산술 포함
- **추가** 최상위 `<~>`가 프로그램의 종료 상태입니다
- **추가** `@ (k, v):쌍들` — 루프 헤더의 패턴
- **추가** `#|c|`가 69개 문자 체계 중 하나에서 숫자를 읽습니다; `#,`와 `#^`는 활성 체계로 숫자를 씁니다

- **변경** 명명된 함수는 호출 시점에 파일의 변수를 값으로 읽습니다
- **변경** 이름만 읽는 문장은 조용히 지나가는 대신 경고합니다
- **엔진** 666개 코퍼스 파일 중 660개가 세 엔진에서 일치, 0개 분기
