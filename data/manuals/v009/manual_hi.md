## चर और स्थिरांक

```zymbol
चर = १०              // परिवर्तनशील चर
PI := ३.१४१५९       // स्थिरांक — पुनः असाइनमेंट रनटाइम त्रुटि है
नाम = "आलिस"
सक्रिय = #१         // बूलियन सत्य
👋 := "नमस्ते"
```

```zymbol
चर = १०    // १०
चर += ५    // १५
चर -= ३    // १२
चर *= २    // २४
चर /= ३    // ८
चर %= ३    // २
चर ^= २    // ४
चर++       // ५
चर--       // ४
```

`°` (डिग्री चिह्न, U+00B0) पहले उपयोग पर एक चर को उसके तटस्थ मान में स्वचालित रूप से आरंभ करता है:

```zymbol
संख्याएँ = [३, १, ४, १, ५]
@ n:संख्याएँ {
    °कुल += n
}
>> कुल ¶              // → 14
```

> `°चर` (उपसर्ग) लूप के ऊपर लंगर डालता है — परिणाम `@` के बाद पढ़ा जा सकता है।
> `चर°` (प्रत्यय) लूप के अंदर लंगर डालता है — जब लूप समाप्त होता है तो मर जाता है।

एक कथन जो केवल एक नाम है, वह चर पढ़ता है और मान को त्याग देता है, इसलिए यह चेतावनी देता है:

```zymbol
गिनती = ५
गिनती
```

संकलक इस प्रकार चेतावनी देता है (संदेश हमेशा अंग्रेज़ी में):

```text

```

## डेटा प्रकार

| प्रकार | लिटरल | `#?` टैग | टिप्पणियाँ |
|------|---------|----------|---------|
| पूर्णांक | `४२`, `-७` | `###` | सुरक्षित पूर्णांक: ±(2⁵³ − 1) |
| फ्लोट | `३.१४`, `१.५e१०` | `##.` | IEEE-754 दोहरा |
| स्ट्रिंग | `"पाठ"` | `##"` | इंटरपोलेशन: `"नमस्ते {नाम}"` |
| कैरेक्टर | `'अ'` | `##'` | एक यूनिकोड ग्राफीम |
| बूलियन | `#१`, `#०` | `##?` | संख्यात्मक नहीं — `#१ ≠ १` |
| ऐरे | `[१, २, ३]` | `##]` | एक प्रकार, जाँचा गया |
| घोषित मिश्रण | `#[१, "दो"]` | `##[` | `[…]` के समान प्रकार, जाँच नहीं |
| टपल | `(अ, ब)` | `##)` | स्थानीय, अपरिवर्तनीय |
| शब्दकोश | `#(अ: १, ब: २)` | `##(` | कुंजीयुक्त, परिवर्तनशील |
| फंक्शन | नामांकित फंक्शन संदर्भ | `##()` | प्रथम-श्रेणी; दिखाता है `<funct/N>` |
| लैम्ब्डा | `अ -> अ * २` | `##->` | प्रथम-श्रेणी; दिखाता है `<lambd/N>` |
| यूनिट | `##_` | `##_` | अनुपस्थिति — कोई null नहीं |

```zymbol
>> ४२#? ¶               // → (###, 2, 42)
>> [१, २, ३]#? ¶        // → (##], 3, [1, 2, 3])
>> #(अ: १)#? ¶          // → (##(, 1, #(अ: 1))
```

एक पूर्णांक जो सुरक्षित सीमा से बाहर जाता है, वह एक पकड़ने योग्य त्रुटि है, कभी भी मूक आवरण नहीं:

```zymbol
!? {
    >> (९००७१९९२५४७४०९९१ + १) ¶
} :! ##Range {
    >> "सीमा से बाहर" ¶ // → सीमा से बाहर
}
```

`##_` वह तरीका है जिससे एक प्रोग्राम पूछता है कि क्या कुछ अनुपस्थित है:

```zymbol
कुछनहीं() { }
मान = कुछनहीं()
>> (मान == ##_) ¶     // → #1
```

## आउटपुट और इनपुट

```zymbol
नाम = "आलिस"
कुल = ३
>> "नमस्ते" ¶             // → नमस्ते
>> "a=" नाम " b=" कुल ¶ // → a=आलिस b=3
>> कुल#? ¶            // → (###, 1, 3)
```

```zymbol
<< नाम
<< "अपना नाम दर्ज करें: " नाम
<< ###(४) "आयु: " आयु
```

**दोनों चिह्नों के आकार को देखें।** `>>` बाहर की ओर इशारा करता है: यह डेटा को प्रोग्राम से बाहर निकालता है। `<<` अंदर की ओर इशारा करता है: यह डेटा को प्रोग्राम में लाता है। वहाँ याद रखने के लिए कुछ नहीं है — तीर दिखाता है कि जानकारी किस दिशा में यात्रा करती है, और वही विचार हर उस चिह्न में वापस आता है जो कुछ स्थानांतरित करता है।

> `¶` और `\\` समतुल्य नई पंक्तियाँ हैं। `>>` कभी भी एक नहीं जोड़ता।
> प्रॉम्प्ट से पहले एक प्रकार निर्दिष्टक पढ़ते समय मान्य करता है और मान्य होने तक पुनः प्रॉम्प्ट करता है:
> `##.` फ्लोट · `##.(T,D)` दशमलव · `###(N)` पूर्णांक · `##"(N)` पाठ · `##'` एक कैरेक्टर।

किसी फ़ाइल के शीर्ष स्तर पर, `<~` प्रोग्राम की निकास स्थिति है:

```zymbol
>> "जाँच कर रहे हैं" ¶      // → जाँच कर रहे हैं
<~ ०
```

## टीयूआई आदिम

इंटरैक्टिव प्रोग्रामों के लिए टर्मिनल UI ऑपरेटर। अधिकांश को `>>| { }` ब्लॉक की आवश्यकता होती है (वैकल्पिक स्क्रीन + कच्चा मोड)।

```zymbol
>>| {
    >>!
    >>~ (१, १, ०, १०) > "चल रहा है"
    @~ १०००
    >>~ (२, १) > "पूर्ण हुआ।"
}
```

```zymbol
>>| {
    [पंक्तियाँ, स्तंभ] = >>?
    >>~ (१, १) > "टर्मिनल: " पंक्तियाँ " x " स्तंभ
    <<| कुंजी
    >>~ (२, १) > "दबाया: " कुंजी
}
```

यहाँ आप देख सकते हैं कि चिह्न क्यों संयोजित होते हैं न कि गुणा होते हैं। आप पहले से जानते हैं कि `<<` इनपुट है और `?` बिना प्रतिबद्ध हुए पूछता है। केवल एक चिह्न नया है:

- `|` एक **एकल इकाई** है, संपूर्ण स्ट्रीम नहीं।

इसके साथ, दोनों कीबोर्ड ऑपरेटर स्वयं पढ़े जाते हैं:

```text
<<        |             ?
इनपुट    एक इकाई      बिना प्रतिबद्ध

<<|   एक कुंजी लें, और तब तक प्रतीक्षा करें जब तक एक न मिल जाए
<<|?  देखें कि क्या कोई कुंजी है, और यदि नहीं तो आगे बढ़ें
```

दूसरी ओर भी यही: `>>` भेजता है, `>>!` **बलपूर्वक** भेजता है (संपूर्ण स्क्रीन साफ़ करता है), और `>>?` लिखने के बजाय **पूछता है** (टर्मिनल कितना बड़ा है)। दाईं ओर का चिह्न वह है जो मोड बदलता है, और यह हमेशा अंत में आता है।

> `>>!` स्क्रीन साफ़ करता है। `>>?` `(पंक्तियाँ, स्तंभ)` लौटाता है। `@~ N` N मिलीसेकंड सोता है।
> `<<|` एक कुंजी दबाव पढ़ता है (अवरोधक); `<<|?` बिना अवरोध के पोल करता है (`'\0'` यदि कोई नहीं)।
> तीर कुंजियाँ `'↑' '↓' '←' '→'` के रूप में डिकोड होती हैं; ESC कोड बिंदु 27 है।
> स्थितिगत आउटपुट टपल: `(पंक्ति, स्तंभ, BKS, अग्र, पृष्ठ)` — कोई भी स्लॉट अल्पविराम से छोड़ा जा सकता है (`>>~ (,,, १९६) > "लाल"`)।
> BKS बिटमास्क: `1`=बोल्ड, `2`=इटैलिक, `4`=अंडरलाइन। ANSI 256-रंग पैलेट (`0`=टर्मिनल डिफ़ॉल्ट)।

## नियंत्रण प्रवाह

```zymbol
अ = ७
? अ > १०० {
    >> "बड़ा" ¶
} _? अ > ० {
    >> "धनात्मक" ¶     // → धनात्मक
} _ {
    >> "ऋणात्मक" ¶
}
```

यहाँ दो नए चिह्न हैं, और तीसरा जो उन्हें एक साथ रखने से आता है:

- `?` **पूछना** है: यह एक शर्त खोलता है।
- `_` **वह है जो निर्दिष्ट नहीं किया गया** था: जब कोई प्रश्न मेल नहीं खाता तो शाखा बची रहती है।
- `_?` दोनों एक पंक्ति में: *यदि कुछ भी मेल नहीं खाया, तो फिर से पूछें*।

यही कारण है कि `_?` इस तरह लिखा जाता है। यह सीखने के लिए एक नया प्रतीक नहीं है — यह `_` है जिसके बाद `?` है, और इसका अर्थ ठीक वही है जो इसके दो भागों का अर्थ है, क्रम में पढ़ा गया।

> `{ }` ब्रेसिज़ एकल कथन के लिए भी **अनिवार्य** हैं।

## मैच

```zymbol
स्कोर = ८५
ग्रेड = ?? स्कोर {
    ९०..१०० => 'अ'
    ८०..८९  => 'ब'
    _       => 'फ'
}
>> ग्रेड ¶              // → ब
```

```zymbol
तापमान = -५
स्थिति = ?? तापमान {
    < ०  => "बर्फ"
    < २० => "ठंडा"
    _    => "गर्म"
}
>> स्थिति ¶              // → बर्फ
```

आप पहले से जानते हैं कि `?` "पूछना" है। **`??` बार-बार पूछना है**: भाषा में कहीं भी किसी चिह्न को दोहराना, वह चिह्न जो एक बार करता है उसे कई बार करना है। एक `?` एक शर्त की जाँच करता है; `??` मामलों की एक सूची के विरुद्ध जाँच करता है।

विकल्प `||` से जुड़ते हैं, और वे पैटर्न प्रकारों को मिश्रित कर सकते हैं:

```zymbol
कुंजी = 'P'
कार्य = ?? कुंजी {
    'p' || 'P' => "रोकें"
    < ० || > १०० => "सीमा से बाहर"
    _ => "अनदेखा"
}
>> कार्य ¶             // → रोकें
```

## लूप

```zymbol
@ i:१..४  { >> i " " }
>> ¶                    // → 1 2 3 4
@ i:१..९:२ { >> i " " }
>> ¶                    // → 1 3 5 7 9
@ i:५..१:१ { >> i " " }
>> ¶                    // → 5 4 3 2 1
```

```zymbol
n = १
@ n <= ६४ { n *= २ }
>> n ¶                  // → 128
```

```zymbol
फल = ["सेब", "नाशपाती", "अंगूर"]
@ f:फल { >> f " " }
>> ¶                    // → सेब नाशपाती अंगूर
@ c:"नमस्ते" { >> c "-" }
>> ¶                    // → न-म-स-्-त-े-
```

```zymbol
@ i:१..१० {
    ? i % २ == ० { @> }
    ? i > ७ { @! }
    >> i " "
}
>> ¶                    // → 1 3 5 7
```

```zymbol
गिनती = ०
@:बाहरी {
    गिनती++
    ? गिनती >= ३ { @:बाहरी! }
}
>> गिनती ¶             // → 3
```

`@` **समय** का चिह्न है: जो कुछ भी दोहराता है वह उसमें रहता है। उस समय को कम करने के लिए आप इसके बगल में एक चिह्न जोड़ते हैं:

- `@!` — `!` **बल** है: अभी लूप छोड़ें।
- `@>` — `>` आगे धकेलता है: अगली बारी पर जाएँ।
- `@:बाहरी!` — `:` **एक नाम बाँधता है**, इसलिए यह *बाहरी* नाम वाले लूप को काटता है, न कि निकटतम को।

तीन ऑपरेटर, और उनमें से किसी को अलग से याद नहीं करना पड़ा: वे `@` हैं और एक चिह्न जो पहले से ही कहता है कि वह क्या करता है।

> **एक निर्दिष्टक एक गिनती या एक शर्त है।** एक `पूर्णांक` एक गिनती है, एक बार मूल्यांकित — `@ ०` शून्य बार शरीर चलाता है। बाकी सब कुछ एक शर्त है। कोई सत्यता नहीं: `@ []` और `@ ३.५` अस्वीकार किए जाते हैं। किसी संग्रह को चलने के लिए `@ x:आइटम` उपयोग करें; इसे गिनने के लिए `@ आइटम$#`।

## फंक्शन

```zymbol
जोड़(अ, ब) { <~ अ + ब }
>> जोड़(३, ४) ¶        // → 7
```

```zymbol
फैक्टोरियल(n) {
    ? n <= १ { <~ १ }
    <~ n * फैक्टोरियल(n - १)
}
>> फैक्टोरियल(५) ¶       // → 120
```

एक फंक्शन फ़ाइल के चरों को मान द्वारा पढ़ता है, और अंदर एक लेखन अंदर ही रहता है:

```zymbol
सीमा = १००
के_अंदर(n) { <~ n < सीमा }
>> के_अंदर(४२) ¶         // → #1
```

दो चिह्न इसे बदलते हैं, और दोनों **हस्ताक्षर और कॉल साइट** पर लिखे जाते हैं:

```zymbol
बढ़ाओ(गणक<~) { गणक = गणक + १ }
कुल = ०
बढ़ाओ(कुल<~)
>> कुल ¶              // → 1
```

> `p~` एक कार्यशील प्रतिलिपि है — शरीर इसे पुनः असाइन कर सकता है और कॉलर अप्रभावित रहता है।
> `p<~` एक आउटपुट पैरामीटर है — परिवर्तन वापस यात्रा करता है। चिह्न के बिना `बढ़ाओ(कुल)` एक अर्थ संबंधी त्रुटि है: एनोटेशन और हस्ताक्षर अलग नहीं हो सकते।

## लैम्ब्डा और क्लोजर

```zymbol
दोगुना = अ -> अ * २
योग = (अ, ब) -> अ + ब
>> दोगुना(५) ¶          // → 10
>> योग(३, ७) ¶          // → 10
```

```zymbol
वर्गीकरण = अ -> {
    ? अ > ० { <~ "धनात्मक" }
    _? अ < ० { <~ "ऋणात्मक" }
    <~ "शून्य"
}
>> वर्गीकरण(-४) ¶         // → ऋणात्मक
```

```zymbol
गुणक = ३
तिगुना = अ -> अ * गुणक
>> तिगुना(७) ¶          // → 21
```

```zymbol
योग_निर्माता(n) { <~ अ -> अ + n }
योग१० = योग_निर्माता(१०)
>> योग१०(५) ¶           // → 15
```

एक लैम्ब्डा कोई पैरामीटर नहीं ले सकता:

```zymbol
उत्तर = () -> ४२
>> उत्तर() ¶           // → 42
```

> एक लैम्ब्डा फ़ाइल के चरों को **बनने पर** पकड़ता है; एक नामांकित फंक्शन उन्हें **कॉल करने पर** पढ़ता है।

## ऐरे

```zymbol
arr = [१, २, ३, ४, ५]
>> arr[१] ¶       // → 1   अनुक्रमण 1-आधारित है
>> arr[-१] ¶      // → 5   ऋणात्मक अंत से गिनती करता है
>> arr$# ¶        // → 5   लंबाई
```

```zymbol
arr = [१, २, ३]
>> (arr$+ ६) ¶          // → [1, 2, 3, 6]   जोड़ें
>> (arr$+[२] ९९) ¶      // → [1, 99, 2, 3]  स्थिति 2 पर डालें
>> (arr$- ३) ¶          // → [1, 2]         पहली घटना हटाएँ
>> (arr$-[१]) ¶         // → [2, 3]         सूचकांक 1 पर हटाएँ
>> (arr$[१..२]) ¶       // → [1, 2]         स्लाइस, दोनों छोर शामिल
>> (arr$? ३) ¶          // → #1             सम्मिलित है
```

ये सभी `$` से शुरू होते हैं, जो **संग्रह** का चिह्न है, और उस चिह्न के साथ जारी रहते हैं जो बताता है कि उसमें क्या किया जाता है: `#` कितने, `+` जोड़ें, `-` हटाएँ, `?` पूछें कि क्या वहाँ है। और जैसे `??` के साथ, चिह्न को दोहराने का अर्थ है इसे संपूर्ण रूप से करना: `$?` पूछता है *क्या* कोई मान मौजूद है, `$??` पूछता है *कितने स्थानों पर* और उन सभी को लौटाता है।

```zymbol
arr = [३, १, २]
>> (arr$^+) ¶     // → [1, 2, 3]   आरोही
>> (arr$^-) ¶     // → [3, 2, 1]   अवरोही
```

**परिणाम का नियम।** एक ऑपरेटर, और आसपास का कोड इसके साथ क्या करता है, यह तय करता है: उपयोग किया गया, यह **निर्माण** करता है और मूल को अकेला छोड़ देता है; त्याग दिया गया, यह **संशोधित** करता है।

```zymbol
arr = [१, २, ३]
प्रतिलिपि = arr[२]$~ ९९
>> arr ¶                // → [1, 2, 3]
>> प्रतिलिपि ¶              // → [1, 99, 3]
arr[२]$~ ९९
>> arr ¶                // → [1, 99, 3]
```

> **`=` कभी भी किसी संग्रह में नहीं लिखता।** `arr[२] = ९९` Zymbol का एक रूप नहीं है — `=` एक नाम को एक मान देता है। किसी संग्रह के भाग को बदलना `$~` है, प्रत्येक संग्रह में।

`[…]` एक प्रकार रखता है और जाँचा जाता है; एक जानबूझकर मिश्रण `#[…]` के साथ **घोषित** किया जाता है:

```zymbol
मिश्रण = #[१, "दो", #१]
>> मिश्रण ¶             // → [1, दो, #1]
>> ([१, २] == #[१, २]) ¶ // → #1
```

## बहुआयामी अनुक्रमण

`>` एक नेस्टेड संरचना में नीचे जाता है। कोष्ठकों का एक समूह एक तत्व को संबोधित करता है, चाहे कितना भी गहरा हो।

```zymbol
m = [[१,२,३], [४,५,६], [७,८,९]]
>> m[२>३] ¶        // → 6   पंक्ति 2, स्तंभ 3
>> m[-१>-१] ¶      // → 9   अंतिम पंक्ति, अंतिम स्तंभ
```

```zymbol
m = [[१,२,३], [४,५,६], [७,८,९]]
>> m[१>१ ; २>२ ; ३>३] ¶          // → [1, 5, 9]          सपाट: विकर्ण
>> m[[१>१, १>३] ; [३>१, ३>३]] ¶  // → [[1, 3], [7, 9]]   संरचित: कोने
```

```zymbol
m = [[१,२,३], [४,५,६]]
>> (m[१>२]$~ ९९) ¶      // → [[1, 99, 3], [4, 5, 6]]
```

> `m[१][२]` Zymbol का एक रूप **नहीं** है। श्रृंखलित सूचकांक पढ़ने और लिखने दोनों के लिए अस्वीकार किया जाता है — प्रति पहुँच एक कोष्ठक समूह, और `>` वह है जो चरणों के बीच जाता है।

## शब्दकोश

नामांकित फ़ील्ड वाला एक टपल एक शब्दकोश है, और v0.0.9 से इसे `#(…)` लिखा जाता है।

```zymbol
व्यक्ति = #(नाम: "आलिस", आयु: २५)
>> व्यक्ति.नाम ¶        // → आलिस
>> व्यक्ति["आयु"] ¶    // → 25
```

```zymbol
व्यक्ति = #(नाम: "आलिस", आयु: २५)
फ़ील्ड = "नाम"
>> व्यक्ति[फ़ील्ड] ¶     // → आलिस
```

यह परिवर्तनशील है, कुंजियाँ जोड़ी जा सकती हैं, और इसे चला जा सकता है:

```zymbol
स्टॉक = #(नाशपाती: ४)
स्टॉक["सेब"]$~ १०
@ k:स्टॉक { >> k "=" स्टॉक[k] " " }
>> ¶                    // → नाशपाती=4 सेब=10
```

```zymbol
स्टॉक = #(नाशपाती: ४, सेब: १०)
@ (k, v):स्टॉक { >> k ":" v " " }
>> ¶                    // → नाशपाती:4 सेब:10
```

> `#()` खाली शब्दकोश है, जो `()` नहीं हो सकता — इसे खाली टपल भी होना पड़ता। नंगे `(a: 1)` को इस संदेश के साथ अस्वीकार किया जाता है: *a dictionary is written `#(…)`* — «एक शब्दकोश `#(…)` लिखा जाता है»।
> एक शब्दकोश को कुंजी द्वारा संबोधित किया जाता है, कभी भी स्थिति द्वारा नहीं, इसलिए `व्यक्ति[१]` एक त्रुटि है।

## टपल

टपल **अपरिवर्तनीय** क्रमबद्ध कंटेनर हैं जो विभिन्न प्रकार के मान धारण करते हैं।

```zymbol
बिंदु = (१०, २०)
>> बिंदु[१] ¶           // → 10
डेटा = (४२, "नमस्ते", #१, ३.१४)
>> डेटा[३] ¶            // → #1
```

```zymbol
t = (१०, २०, ३०)
t2 = t[२]$~ ९९९
>> t ¶                  // → (10, 20, 30)
>> t2 ¶                 // → (10, 999, 30)
```

> किसी टपल को उसी स्थान पर संशोधित करने का कोई भी प्रयास एक त्रुटि है, चाहे ऑपरेटर कोई भी हो — अपरिवर्तनीयता मान का एक गुण है, प्रत्येक `$` के अंदर कोई अपवाद नहीं।

## विघटन

```zymbol
arr = [१०, २०, ३०, ४०, ५०]
[अ, ब, स] = arr
>> अ " " ब " " स ¶      // → 10 20 [30, 40, 50]
```

```zymbol
arr = [१०, २०, ३०, ४०, ५०]
[पहला, *शेष] = arr
>> पहला ¶              // → 10
>> शेष ¶               // → [20, 30, 40, 50]
```

```zymbol
बिंदु = (१००, २००)
(px, py) = बिंदु
>> px " " py ¶          // → 100 200
```

```zymbol
व्यक्ति = #(नाम: "आना", आयु: २५)
#(नाम: n, आयु: a) = व्यक्ति
>> n " " a ¶            // → आना 25
```

> कोष्ठक का आकार टाइप किया गया है: `[…]` एक ऐरे लेता है, `(…)` एक टपल, `#(…)` एक शब्दकोश। अंतिम नाम **शेष को अवशोषित** करता है, इसलिए विघटन कभी भी लंबाई पर विफल नहीं होता — `(a, b, c) = (1,2,3,4,5)` देता है `c = (3,4,5)`, और `##_` जब कुछ नहीं बचता।

## उच्च-क्रम फंक्शन

```zymbol
संख्याएँ = [१, २, ३, ४, ५]
>> (संख्याएँ$> (अ -> अ * २)) ¶ // → [2, 4, 6, 8, 10]
>> (संख्याएँ$| (अ -> अ % २ == ०)) ¶ // → [2, 4]
>> (संख्याएँ$< (०, (संचयक, अ) -> संचयक + अ)) ¶ // → 15
```

```zymbol
संख्याएँ = [१, २, ३, ४, ५, ६]
दोगुना(अ) { <~ अ * २ }
बड़ा_है(अ) { <~ अ > ३ }
>> (संख्याएँ$> दोगुना) ¶    // → [2, 4, 6, 8, 10, 12]
>> (संख्याएँ$| बड़ा_है) ¶    // → [4, 5, 6]
```

```zymbol
डेटाबेस = [#(नाम: "कार्ला", आयु: २८), #(नाम: "आना", आयु: २५)]
आयु_अनुसार = डेटाबेस$^ (अ, ब -> अ.आयु < ब.आयु)
>> आयु_अनुसार[१].नाम ¶     // → आना
```

> एक नामांकित फंक्शन HOF में **बिना कोष्ठक** के जाता है: `संख्याएँ$> दोगुना`। `संख्याएँ$> (दोगुना)` लिखना एक पार्स त्रुटि है, क्योंकि `(` एक लैम्ब्डा खोलता है।

दोगुना = अ -> अ * २

## त्रुटि हैंडलिंग

```zymbol
!? {
    अ = १० / ०
} :! ##Div {
    >> "शून्य से विभाजन" ¶  // → शून्य से विभाजन
} :! {
    >> "अन्य: " _err ¶
} :> {
    >> "हमेशा चलता है" ¶        // → हमेशा चलता है
}
```

| प्रकार | कब |
|------|------|
| `##Div` | शून्य से विभाजन |
| `##Index` | सूचकांक सीमा से बाहर |
| `##Key` | शब्दकोश में कुंजी नहीं |
| `##Range` | सुरक्षित पूर्णांक सीमा से बाहर |
| `##Type` | प्रकार बेमेल |
| `##Parse` | डेटा पार्सिंग |
| `##IO` | फ़ाइल / सिस्टम |
| `##Network` | नेटवर्क त्रुटियाँ |
| `##DB` | डेटाबेस |
| `##Time` | एक तारीख जो अस्तित्व में नहीं है |
| `##_` | कोई भी त्रुटि (सब-पकड़ने वाला) |

`!` **त्रुटि और बल** का चिह्न है, और यह दोनों परिवारों में समान पढ़ा जाता है: `$!` किसी मान से पूछता है कि क्या वह त्रुटि है; `$!!`, चिह्न दोगुना होने पर, बिना पूछे इसे ऊपर प्रसारित करता है।

> मानक पुस्तकालय की विफलताएँ **सॉफ्ट त्रुटि मान** के रूप में वापस आती हैं जिन्हें आप `$!` से जाँचते हैं या `!?` से पकड़ते हैं, बजाय समाप्त करने के। `$!!` एक को कॉलर तक प्रसारित करता है।

## मॉड्यूल

```zymbol
# कैल्क {
    #> { जोड़, PI }

    PI := ३.१४१५९
    जोड़(अ, ब) { <~ अ + ब }
}
```

```zymbol
<# ./कैल्क => c

>> c::जोड़(५, ३) ¶
>> c.PI ¶
```

```zymbol
# मायलिब {
    #> { आंतरिक_जोड़ => योग }

    आंतरिक_जोड़(अ, ब) { <~ अ + ब }
}
```

दोनों मॉड्यूल चिह्न फिर से वही विचार हैं, अब फ़ाइलों पर लागू: `#` **घोषणा** का स्तर है — एक चीज़ *क्या है*, न कि उसका मूल्य — और तीर बताता है कि कोड किस दिशा में जाता है:

```text
<#   तीर प्रवेश करता है: आयात करें, दूसरी फ़ाइल से लाएँ
#>   तीर निकलता है: निर्यात करें, अन्य फ़ाइलों को प्रदान करें
```

एक दिशा चिह्न हमेशा उस किनारे पर बैठता है जिस ओर वह इशारा करता है। यही कारण है कि `<~` बाईं ओर लौटता है (फंक्शन से बाहर) और `->` दाईं ओर प्रवेश करता है (लैम्ब्डा के शरीर में)।

> **एक मॉड्यूल घोषित करता है कि वह क्या निर्यात करता है।** `#>` ब्लॉक अनिवार्य है — इसे छोड़ना **E014** है, और `#> { }` वह तरीका है जिससे एक मॉड्यूल कहता है कि उसकी सतह खाली है। `::` एक फंक्शन को कॉल करता है, `.` एक स्थिरांक पढ़ता है। मॉड्यूल बॉडी में केवल आयात, निर्यात ब्लॉक, शाब्दिक आरंभकर्ता और फंक्शन परिभाषाएँ दिखाई दे सकती हैं; कोई भी निष्पादन योग्य चीज़ **E013** है।

## मानक पुस्तकालय

मूल मॉड्यूल, किसी अन्य की तरह आयात किए जाते हैं:

| मॉड्यूल | फंक्शन |
|--------|-----------|
| `std/math` | `sqrt exp ln log pow abs ceil floor round min max sin cos tan` · `PI` `E` |
| `std/random` | `entero rango peso_f64` |
| `std/json` | `decode decode_map encode` |
| `std/io` | `read write append exists delete list mkdir` |
| `std/net` | `get post post_json head` |
| `std/db` | `connect exec query query_one tx commit rollback` … |
| `std/term` | `width pad_left pad_right center truncate` |
| `std/time` | `now today parts of format add diff` |

```zymbol
<# std/math => m

>> m::sqrt(१६.०) ¶      // → 4
>> m.PI ¶               // → 3.141592653589793
```

```zymbol
<# std/term => t

>> t::width("手番") ¶            // → 4   दो ग्लिफ़, चार स्तंभ
>> "|" t::center("go", 8) "|" ¶ // → |   go   |
```

```zymbol
<# std/time => T

दिन = T::of(२०२६, १, ३१)
>> T::format(दिन, "%Y-%m-%d") ¶ // → 2026-01-31
>> T::format(T::add(दिन, 1, "month"), "%Y-%m-%d") ¶ // → 2026-02-28
```

> `std/term` **प्रदर्शन स्तंभ** मापता है, वर्ण नहीं: CJK और अधिकांश इमोजी 2 स्तंभ हैं, इसलिए `t::width` के साथ एक तालिका बिछाएँ, कभी भी `$#` नहीं।
> `std/time` में एक क्षण युग के बाद मिलीसेकंड है। एक दिन से कम अवधि है, एक दिन से ऊपर कैलेंडर है — इसलिए एक महीना उसी दिन पड़ता है, क्लैम्प किया हुआ। `diff(a, b)` `a - b` है, इसलिए पहले का क्षण पहले देने पर ऋणात्मक उत्तर मिलता है।

## पैकेज

एक `.zyp` एक बहु-फ़ाइल प्रोग्राम को एक पोर्टेबल फ़ाइल में बंडल करता है। यह **स्रोत** का एक संग्रह है, बाइनरी नहीं, इसलिए यह कहीं भी चलता है जहाँ `zymbol` बाइनरी चलती है।

```bash
zymbol package myproject/ --script main.zy -o myproject.zyp
zymbol run myproject.zyp
```

> संग्रह एक मेनिफेस्ट (`zyp.toml`) रखता है जो इसके प्रवेश स्क्रिप्ट और उस इंजन संस्करण को घोषित करता है जिसकी उसे आवश्यकता है। `zymbol run` इसे एक अस्थायी निर्देशिका में निकालता है और वहाँ से चलाता है, इसलिए कोड डिस्पोज़ेबल है जबकि स्क्रिप्ट जो कुछ भी लिखती है वह आपके वास्तविक कार्यशील निर्देशिका में आता है। Playground भी `.zyp` फ़ाइलें लोड करता है।

## अंकीय मोड

Zymbol संख्याओं को **69 यूनिकोड अंक लिपियों** में लिख सकता है — देवनागरी, अरबी-भारतीय, थाई, क्लिंगॉन pIqaD, गणितीय बोल्ड, LCD खंड, और बहुत कुछ। मोड प्रक्रिया के लिए वैश्विक है और आउटपुट को प्रभावित करता है; अंकगणित अपरिवर्तित है।

```zymbol
#०९#    // देवनागरी   (U+0966–U+096F)
#٠٩#    // अरबी-भारतीय (U+0660–U+0669)
#๐๙#    // थाई         (U+0E50–U+0E59)
#09#    // ASCII पर रीसेट करें
```

```zymbol
अ = ४२
>> अ ¶                  // → 42
#०९#
>> अ ¶                  // → ४२
>> ३.१४ ¶               // → ३.१४
>> #१ ¶                 // → #१
#09#
```

किसी भी समर्थित लिपि के अंक स्रोत में मान्य लिटरल हैं:

```zymbol
#०९#
@ i:१..५ { >> i " " }
>> ¶                    // → १ २ ३ ४ ५
#09#
```

पढ़ना सममित है — एक अंक किसी भी लिपि में समझा जाता है:

```zymbol
>> #|"४२"| ¶            // → 42
>> #|'७'| ¶             // → 7
```

> `#` हमेशा ASCII है, इसलिए `#0` हर लिपि में अंक शून्य से दृष्टिगत रूप से अलग रहता है।
> `#,` और `#^` भी अपने अंक सक्रिय लिपि में लिखते हैं, और विभाजक उसका अनुसरण करते हैं — लेकिन युग्म कभी नहीं उलटता: `,` समूह बनाता है और `.` विभाजित करता है, हर लिपि में।

## डेटा ऑपरेटर

```zymbol
f = ##.४२         // फ्लोट में
i = ###३.७        // पूर्णांक में, गोल  → 4
t = ##!३.७        // पूर्णांक में, काटें  → 3
>> f " " i " " t ¶      // → 42 4 3
>> f#? ¶                // → (##., 2, 42)
```

> एक फ्लोट अंकों के रूप में प्रिंट होता है, कभी भी घातांक के रूप में नहीं, और अंतिम `.0` छोड़ देता है — `##.42` `42` लिखता है और फिर भी फ्लोट है, जैसा `f#?` दिखाता है।

```zymbol
>> #|"४२"| ¶       // → 42
>> #|"abc"| ¶      // → abc   विफल-सुरक्षित: इनपुट को अपरिवर्तित लौटाता है
>> ##!'A' ¶        // → 65    एक कैरेक्टर का कोड बिंदु
```

```zymbol
π = ३.१४१५९२६५
>> #.२|π| ¶       // → 3.14          2 दशमलव स्थानों पर गोल
>> #!२|π| ¶       // → 3.14          2 दशमलव स्थानों पर काटें
>> #,|१२३४५६७| ¶   // → 1,234,567    हज़ार विभाजक
>> #^|१२३४५.६७८| ¶ // → 1.2345678e4  वैज्ञानिक संकेतन
```

```zymbol
>> 0x41 ¶        // → A   हेक्स
>> 0b01000001 ¶  // → A   बाइनरी
>> 0o101 ¶       // → A   ऑक्टल
>> 0d65 ¶        // → A   दशमलव
```

> ASCII सीमा में एक आधार लिटरल एक **कैरेक्टर** है: `0d65 == 'A'` `#1` है, और `0d65 == 65` `#0` है। सभी चार आधार एक ही कैरेक्टर की वर्तनी करते हैं।

## चिह्न कैसे संयोजित होते हैं

आप इस मैनुअल में एक ही चीज़ बार-बार देख रहे हैं: **एक ऑपरेटर याद रखने के लिए एक चित्र नहीं है, यह एक पंक्ति में कई चिह्न हैं, और प्रत्येक अपना अर्थ योगदान देता है।** अब जब आप उन सभी को जानते हैं, तो यहाँ संपूर्ण पैटर्न है।

पहले आता है **हम किस दुनिया में हैं**:

| चिह्न | दुनिया | आपने इसे कहाँ देखा |
|------|-------|-------------|
| `$` | एक संग्रह | `$#` `$+` `$?` `$^-` |
| `@` | समय, जो कुछ भी दोहराता है | `@!` `@>` `@~` |
| `#` | एक चीज़ *क्या है*, न कि उसका मूल्य | `#?` `#(…)` `<#` `#>` |
| `>>` | प्रोग्राम से बाहर | `>>` `>>!` `>>?` |
| `<<` | प्रोग्राम में अंदर | `<<` `<<\|` `<<\|?` |
| `?` | पूछना, बिना प्रतिबद्ध | `?` `_?` `??` `$?` |
| `!` | बल, या त्रुटि | `@!` `$!` `!?` |

फिर आता है **वहाँ क्या किया जाता है**: `+` जोड़ें, `-` हटाएँ, `^` क्रम, `~` संशोधित करें, `#` गिनती, `|` एक एकल इकाई, `:` नाम बाँधें।

और दो नियम जो कभी विफल नहीं होते:

**एक चिह्न को दोहराना इसे संपूर्ण बनाता है।** `?` एक बार पूछता है, `??` कई मामलों की जाँच करता है। `$?` पूछता है कि क्या कोई मान वहाँ है, `$??` हर स्थान लौटाता है जहाँ यह है। `!` एक त्रुटि को चिह्नित करता है, `!!` बिना पूछे इसे प्रसारित करता है।

**मोड चिह्न हमेशा अंत में आता है।** जब `?` या `!` यह कहने के लिए प्रकट होते हैं कि कुछ *कैसे* किया जाता है — अनिश्चित रूप से या बलपूर्वक — वे ऑपरेटर के अंतिम चिह्न होते हैं: `$??`, `$!!`, `<<|?`, `@!`, `##!`, `>>!`, `>>?`, `@:बाहरी!`। उनके बाद कभी कोई संचालन नहीं होता।

इससे एक व्यावहारिक बात निकलती है: **एक संयोजन जो आपने कभी नहीं देखा, उसे देखने से पहले ही समझ में आता है।** यदि `$` संग्रह है और `^` क्रम है और `-` उल्टा है, तो `$^-` अवरोही क्रम में सजाता है, और किसी को आपको बताने की आवश्यकता नहीं थी।

संपूर्ण सूची इस तरह काम नहीं करती, और यह कहना बेहतर है। अधिकांश ऑपरेटर साफ-साफ अलग हो जाते हैं। छह अलग हो जाते हैं लेकिन अपने भागों से अधिक अर्थ रखते हैं: `!?` `:!` `:>` `|>` `::` `$++`। और दस को कंठस्थ करना पड़ता है क्योंकि वे बिल्कुल भी अलग नहीं होते: `¶` `><` `#1` `#0` `0x` `0b` `0o` `0d` `###` `°`।

> अपारदर्शी को गिनना बजाय यह मान लेना कि वे कम हैं, जानबूझकर किया गया है: वे भाषा की वास्तविक स्मरण लागत हैं। पूर्ण संदर्भ — सूची, घोषित समलिखित शब्द, और नियम जिन्हें एक नए ऑपरेटर को संतुष्ट करना चाहिए — इंटरप्रेटर रिपॉजिटरी में `SYMBOLS.md` में है।

| `>>\|` | TUI ब्लॉक (वैकल्पिक स्क्रीन) | `>>~` | स्थितिगत आउटपुट |
| `>>!` | स्क्रीन साफ़ करें | `>>?` | टर्मिनल आकार पूछें |
| `<<\|` | अवरोधक कुंजी दबाव | `<<\|?` | गैर-अवरोधक कुंजी दबाव |
| `@~ N` | N मिलीसेकंड सोएँ | `0d` `0x` `0o` `0b` | आधार लिटरल |

## रिलीज़ चेंजलॉग

### v0.0.9 — संग्रह निर्णय _(सितंबर 2026)_

- **ब्रेकिंग** शब्दकोश की अपनी संकेतन है: `#(कुंजी: मान)`। नंगे `(a: 1)` को अस्वीकार कर दिया गया है, और `#()` खाली शब्दकोश है — जो `()` कभी नहीं हो सकता
- **ब्रेकिंग** अनुक्रमित असाइनमेंट वापस ले लिया गया: `arr[i] = v` और सभी यौगिक रूप। `=` एक नाम को मान देता है; किसी संग्रह के भाग को बदलना `$~` है
- **ब्रेकिंग** श्रृंखलित सूचकांक `m[i][j]` को पढ़ने और लिखने दोनों के लिए अस्वीकार कर दिया गया — `>` वह है जो चरणों के बीच जाता है
- **ब्रेकिंग** एक मॉड्यूल को घोषित करना चाहिए कि वह क्या निर्यात करता है (**E014**); `#> { }` कहता है कि सतह खाली है
- **ब्रेकिंग** एक लूप निर्दिष्टक एक गिनती या एक शर्त है — कोई सत्यता नहीं। `@ []` और `@ 3.5` अस्वीकार किए जाते हैं
- **जोड़ा गया** `##_` — यूनिट लिटरल, और एक प्रोग्राम कैसे पूछता है कि क्या कुछ अनुपस्थित है
- **जोड़ा गया** `#[…]` — एक ऐरे जिसके तत्व प्रकारों का मिश्रण घोषित किया गया है
- **जोड़ा गया** `#?` चार संग्रहों को अलग बताता है: `##]` `##[` `##)` `##(`
- **जोड़ा गया** `std/time` — घड़ी और नागरिक कैलेंडर, क्षेत्रों और कैलेंडर अंकगणित के साथ
- **जोड़ा गया** एक शीर्ष-स्तरीय `<~` प्रोग्राम की निकास स्थिति है
- **जोड़ा गया** `@ (k, v):जोड़े` — लूप शीर्ष में एक पैटर्न
- **जोड़ा गया** `#|c|` 69 लिपियों में से किसी में एक अंक पढ़ता है; `#,` और `#^` अपने अंक सक्रिय में लिखते हैं
- **बदला गया** `पूर्णांक` एक सुरक्षित पूर्णांक है, ±(2⁵³ − 1), हर इंजन में विफल-बंद
- **बदला गया** एक नामांकित फंक्शन फ़ाइल के चरों को कॉल समय पर, मान द्वारा पढ़ता है
- **बदला गया** एक कथन जो केवल एक नाम पढ़ता है, चुपचाप पास होने के बजाय चेतावनी देता है
- **इंजन** 660 में से 666 कोरपस फ़ाइलें तीनों इंजनों में सहमत, 0 भिन्न

### v0.0.8 — स्वत: मुक्ति, `std/term` और पैकेज _(अगस्त 2026)_

- **जोड़ा गया** अंतिम उपयोग पर स्वचालित विनाश — अदृश्य; केवल पीक मेमोरी कम करता है
- **जोड़ा गया** `std/term` — टर्मिनल स्तंभों में प्रदर्शन मेट्रिक्स
- **जोड़ा गया** एक `कैरेक्टर` पर `##!` — इसका यूनिकोड कोड बिंदु
- **जोड़ा गया** मैच या-पैटर्न: `'p' || 'P' => …`, एक शाखा में किसी भी प्रकार के विकल्प
- **जोड़ा गया** Zymbol पैकेज (`.zyp`) — `zymbol package` / `zymbol run pkg.zyp`
- **जोड़ा गया** कॉल साइट पर `<~` आवश्यक है जहाँ कैली घोषित करता है कि एक आउटपुट पैरामीटर है
- **सुधारा गया** रजिस्टर VM में मॉड्यूल सिस्टम समता

### v0.0.7 — मूल मानक पुस्तकालय _(जुलाई 2026)_

- **जोड़ा गया** `std/json`, `std/io`, `std/net`, `std/db` (ODBC) — सभी सॉफ्ट त्रुटि मानों के साथ
- **जोड़ा गया** टाइप/सत्यापित इनपुट: `<< ##.(5,2) "मूल्य: " p`
- **जोड़ा गया** `>>` में सीधे पोस्टफिक्स ऑपरेटर — कोष्ठक की आवश्यकता नहीं
- **बदला गया** विफल-बंद फ़ॉर्मेटर: वह आउटपुट लिखने से इनकार करता है जिसे वह पुनः पढ़ नहीं सकता
