# Zymbol-Lang マニュアル

> **v0.0.9 向けに改訂 — 2026-09-07**

**Zymbol-Lang** はシンボリックプログラミング言語です。その文法には単語がなく、すべての構文は記号です。あらゆる人間の言語で同一に動作します。

- `if`、`while`、`return` はありません — `?`、`@`、`<~` のみ
- 完全な Unicode — 任意の言語や絵文字での識別子
- 人間言語に依存しない — コードはどこでも同じです

**インタープリターバージョン**: v0.0.9 | **テストカバレッジ**: 660/666（3つのエンジンが合意、0件の相違）

## 変数と定数

```zymbol
変数 = 10              // 可変変数
PI := 3.14159       // 定数 — 再代入は実行時エラー
名前 = "田中"
有効 = #1           // ブール値 true
👋 := "こんにちは"
```

```zymbol
変数 = 10    // 10
変数 += 5    // 15
変数 -= 3    // 12
変数 *= 2    // 24
変数 /= 3    // 8
変数 %= 3    // 2
変数 ^= 2    // 4
変数++       // 5
変数--       // 4
```

`°`（度記号、U+00B0）は、最初の使用時に変数をその中立値に自動初期化します:

```zymbol
数列 = [3, 1, 4, 1, 5]
@ n:数列 {
    °合計 += n
}
>> 合計 ¶              // → 14
```

> `°変数`（接頭辞）はループの上にアンカーします — 結果は `@` の後に読み取り可能です。
> `変数°`（接尾辞）はループの内部にアンカーします — ループが終了すると消滅します。

名前だけの文は変数を読み取って値を破棄するため、警告を発します:

```zymbol
カウンタ = 5
カウンタ
```

コンパイラは次のように警告します（メッセージは常に英語です）:

```text
warning: this statement does nothing: 'カウンタ' is read and discarded
  = help: remove it, or use it — `>> name ¶` to print it
```

つまり: *「この文は何も行いません: 'カウンタ' が読み取られて破棄されました」*。

## データ型

| 型 | リテラル | `#?` タグ | 備考 |
|------|---------|-----------|------|
| 整数 | `42`, `-7` | `###` | 安全な整数: ±(2⁵³ − 1) |
| 浮動小数 | `3.14`, `1.5e10` | `##.` | IEEE-754 倍精度 |
| 文字列 | `"テキスト"` | `##"` | 補間: `"こんにちは {名前}"` |
| 文字 | `'A'` | `##'` | 1つのUnicodeコードポイント |
| ブール | `#1`, `#0` | `##?` | 数値ではない — `#1 ≠ 1` |
| 配列 | `[1, 2, 3]` | `##]` | 単一型、検査済み |
| 宣言済み混合 | `#[1, "二"]` | `##[` | `[…]` と同じ型、検査なし |
| タプル | `(甲, 乙)` | `##)` | 位置指定、不変 |
| 辞書 | `#(甲: 1, 乙: 2)` | `##(` | キー付き、可変 |
| 関数 | 名前付き関数参照 | `##()` | 第一級; 表示 `<funct/N>` |
| ラムダ | `甲 -> 甲 * 2` | `##->` | 第一級; 表示 `<lambd/N>` |
| ユニット | `##_` | `##_` | 不在 — null は存在しません |

```zymbol
>> 42#? ¶               // → (###, 2, 42)
>> [1, 2, 3]#? ¶        // → (##], 3, [1, 2, 3])
>> #(甲: 1)#? ¶          // → (##(, 1, #(甲: 1))
```

安全な範囲を超える整数は捕捉可能なエラーであり、決して静かなラップアラウンドではありません:

```zymbol
!? {
    >> (9007199254740991 + 1) ¶
} :! ##Range {
    >> "範囲外" ¶ // → 範囲外
}
```

`##_` はプログラムが何かが存在しないかどうかを問い合わせる方法です:

```zymbol
無() { }
値 = 無()
>> (値 == ##_) ¶     // → #1
```

## 出力と入力

```zymbol
名前 = "田中"
合計 = 3
>> "こんにちは" ¶             // → こんにちは
>> "a=" 名前 " b=" 合計 ¶ // → a=田中 b=3
>> 合計#? ¶            // → (###, 1, 3)
```

```zymbol
<< 名前
<< "名前を入力してください: " 名前
<< ###(4) "年齢: " 年齢
```

**2つの記号の形を見てください。** `>>` は外側を指しています: プログラムからデータを取り出します。`<<` は内側を指しています: データをプログラムに取り込みます。そこには覚えることは何もありません — 矢印は情報がどの方向に移動するかを示し、その同じ考えが何かを移動させるすべての記号に戻ってきます。

> `¶` と `\\` は同等の改行です。`>>` は決して改行を追加しません。
> プロンプトの前の型指定子は読み取り時に検証し、値が有効になるまで再プロンプトします:
> `##.` 浮動小数 · `##.(T,D)` 小数 · `###(N)` 整数 · `##"(N)` テキスト · `##'` 1文字。

ファイルの最上位では、`<~` はプログラムの終了ステータスです:

```zymbol
>> "チェック中" ¶      // → チェック中
<~ 0
```

## TUIプリミティブ

対話型プログラムのための端末UIオペレーター。ほとんどは `>>| { }` ブロック（代替画面 + 生モード）を必要とします。

```zymbol
>>| {
    >>!
    >>~ (1, 1, 0, 10) > "実行中"
    @~ 1000
    >>~ (2, 1) > "完了。"
}
```

```zymbol
>>| {
    [行, 列] = >>?
    >>~ (1, 1) > "端末: " 行 " x " 列
    <<| キー
    >>~ (2, 1) > "押された: " キー
}
```

ここで、記号がなぜ掛け算ではなく組み合わされるのかがわかります。`<<` が入力であり、`?` がコミットせずに尋ねることは既に知っています。新しい記号は1つだけです:

- `|` は **単一のユニット** であり、ストリーム全体ではありません。

これにより、両方のキーボードオペレーターが自明になります:

```text
<<        |             ?
入力      単一ユニット   コミットせず

<<|   1つのキーを取得し、キーが来るまで待つ
<<|?  キーが存在するか確認し、なければ続行する

```

反対側も同様です: `>>` は送信し、`>>!` は **強制的に** 送信（画面全体をクリア）し、`>>?` は書く代わりに **尋ねます**（端末のサイズ）。右側の記号がモードを変更するもので、常に最後に来ます。

> `>>!` は画面をクリアします。`>>?` は `(行, 列)` を返します。`@~ N` は N ミリ秒スリープします。
> `<<|` は1回のキー入力を読み取ります（ブロッキング）; `<<|?` はブロッキングせずにポーリングします（なしの場合は `'\0'`）。
> 矢印キーは `'↑' '↓' '←' '→'` としてデコードされます; ESC はコードポイント27です。
> 位置指定出力タプル: `(行, 列, BKS, 前景, 背景)` — 任意のスロットはカンマで省略可能（`>>~ (,,, 196) > "赤"`）。
> BKS ビットマスク: `1`=太字, `2`=斜体, `4`=下線。ANSI 256色パレット（`0`=端末デフォルト）。

## オペレーター

```zymbol
甲 = 10
乙 = 3
結果1 = 甲 + 乙    // 13
結果2 = 甲 - 乙    // 7
結果3 = 甲 * 乙    // 30
結果4 = 甲 / 乙    // 3  (整数除算)
結果5 = 甲 % 乙    // 1
結果6 = 甲 ^ 乙    // 1000
```

```zymbol
甲 = 10
乙 = 3
比較1 = 甲 == 乙    // #0
比較2 = 甲 <> 乙    // #1
比較3 = 甲 < 乙     // #0
比較4 = 甲 >= 乙    // #1
論理1 = #1 && #0  // #0
論理2 = !#1       // #0
```

> `==` は決して型変換しません: `"5" == 5` は `#0` です。順序付けは変換します: `"5" > 4` は `#1` であり、`"४२" > 5` も同様です — 69の文字体系のいずれかの数値テキストは数値として比較されます。
> 関数は自身にのみ等しく、同じ本体を持つ別の関数には決して等しくなりません。

## 文字列

```zymbol
名前 = "田中"
n = 42
>> "こんにちは " 名前 " さん、あなたは " n " をお持ちです" ¶ // → こんにちは 田中 さん、あなたは 42 をお持ちです
説明 = "こんにちは {名前} さん、あなたは {n} をお持ちです"
>> 説明 ¶              // → こんにちは 田中 さん、あなたは 42 をお持ちです
```

```zymbol
s = "こんにちは世界"
長さ = s$#                  // 7
部分 = s$[1..5]             // "こんにちは"
含む = s$? "世界"          // #1
分割 = "a,b,c,d"$/ ','    // [a, b, c, d]
置換 = s$~~["に":"ー"]        // "こんーちは世界"
線 = "─" $* 20
```

> `+` は数値専用です。文字列には併置または補間を使用してください。
> `\{` と `\}` はリテラルの中括弧です — エスケープは対称です。

## 制御フロー

```zymbol
甲 = 7
? 甲 > 100 {
    >> "大きい" ¶
} _? 甲 > 0 {
    >> "正" ¶     // → 正
} _ {
    >> "負" ¶
}
```

ここに2つの新しい記号があり、3つ目はそれらを組み合わせたものです:

- `?` は **尋ねる** です: 条件を開きます。
- `_` は **指定されなかったもの** です: どの質問も一致しなかったときに残る分岐です。
- `_?` は両方を続けて: *何も一致しなかった場合、もう一度尋ねる*。

これが `_?` がそのように書かれている理由です。それは学習すべき新しい記号ではなく、`_` の後に `?` が続くものであり、その2つの部分が順に読まれて意味することを正確に意味します。

> 中括弧 `{ }` は単一の文でも **必須** です。

## マッチ

```zymbol
点数 = 85
評価 = ?? 点数 {
    90..100 => '優'
    80..89  => '良'
    _       => '不'
}
>> 評価 ¶              // → 良
```

```zymbol
温度 = -5
状態 = ?? 温度 {
    < 0  => "氷"
    < 20 => "冷たい"
    _    => "熱い"
}
>> 状態 ¶              // → 氷
```

`?` が「尋ねる」であることは既に知っています。**`??` は何度も尋ねることです**: 言語のどこでも記号を2倍にすることは、その記号が1回行うことを何度も行うことです。1つの `?` は条件をテストします; `??` はケースのリストに対してテストします。

代替案は `||` で結合され、パターンの種類を混在させることができます:

```zymbol
キー = 'P'
アクション = ?? キー {
    'p' || 'P' => "一時停止"
    < 0 || > 100 => "範囲外"
    _ => "無視"
}
>> アクション ¶             // → 一時停止
```

## ループ

```zymbol
@ i:1..4  { >> i " " }
>> ¶                    // → 1 2 3 4
@ i:1..9:2 { >> i " " }
>> ¶                    // → 1 3 5 7 9
@ i:5..1:1 { >> i " " }
>> ¶                    // → 5 4 3 2 1
```

```zymbol
数 = 1
@ 数 <= 64 { 数 *= 2 }
>> 数 ¶                  // → 128
```

```zymbol
果物 = ["リンゴ", "ナシ", "ブドウ"]
@ f:果物 { >> f " " }
>> ¶                    // → リンゴ ナシ ブドウ
@ c:"こんにちは" { >> c "-" }
>> ¶                    // → こ-ん-に-ち-は-
```

```zymbol
@ i:1..10 {
    ? i % 2 == 0 { @> }
    ? i > 7 { @! }
    >> i " "
}
>> ¶                    // → 1 3 5 7
```

```zymbol
カウンタ = 0
@:外部 {
    カウンタ++
    ? カウンタ >= 3 { @:外部! }
}
>> カウンタ ¶             // → 3
```

`@` は **時間** の記号です: 繰り返されるすべてのものがその中に存在します。その時間を短くするには、隣に記号を追加します:

- `@!` — `!` は **強制** です: 今すぐループを抜けます。
- `@>` — `>` は前方に押し出します: 次の回に進みます。
- `@:外部!` — `:` は **名前を束縛** するため、これは *外部* という名前のループを切断し、最も近いループではありません。

3つのオペレーターは、どれも個別に覚える必要はありませんでした: それらは `@` に、すでにその動作を表す記号を加えたものです。

> **指定子はカウントまたは条件です。** `整数` はカウントであり、1回評価されます — `@ 0` は本体を0回実行します。それ以外はすべて条件です。真理値はありません: `@ []` と `@ 3.5` は拒否されます。コレクションを走査するには `@ x:要素` を使用し、カウントするには `@ 要素$#` を使用します。

## 関数

```zymbol
加算(甲, 乙) { <~ 甲 + 乙 }
>> 加算(3, 4) ¶        // → 7
```

```zymbol
階乗(n) {
    ? n <= 1 { <~ 1 }
    <~ n * 階乗(n - 1)
}
>> 階乗(5) ¶       // → 120
```

関数はファイルの変数を値で読み取り、内部での書き込みは内部に留まります:

```zymbol
制限 = 100
内部(n) { <~ n < 制限 }
>> 内部(42) ¶         // → #1
```

2つの記号がそれを変更し、両方とも **シグネチャと呼び出しサイト** に記述されます:

```zymbol
増加(カウンタ<~) { カウンタ = カウンタ + 1 }
合計 = 0
増加(合計<~)
>> 合計 ¶              // → 1
```

> `p~` は作業用コピーです — 本体はそれを再代入でき、呼び出し元は影響を受けません。
> `p<~` は出力パラメーターです — 変更は戻ります。記号なしの `増加(合計)` は意味エラーです: アノテーションとシグネチャが乖離することはできません。

## ラムダとクロージャ

```zymbol
二倍 = 甲 -> 甲 * 2
和 = (甲, 乙) -> 甲 + 乙
>> 二倍(5) ¶          // → 10
>> 和(3, 7) ¶          // → 10
```

```zymbol
分類 = 甲 -> {
    ? 甲 > 0 { <~ "正" }
    _? 甲 < 0 { <~ "負" }
    <~ "零"
}
>> 分類(-4) ¶         // → 負
```

```zymbol
因子 = 3
三倍 = 甲 -> 甲 * 因子
>> 三倍(7) ¶          // → 21
```

```zymbol
加算器作成(n) { <~ 甲 -> 甲 + n }
加算10 = 加算器作成(10)
>> 加算10(5) ¶           // → 15
```

ラムダはパラメーターをまったく取らないこともできます:

```zymbol
答え = () -> 42
>> 答え() ¶           // → 42
```

> ラムダはファイルの変数を **作成時に** 捕捉します; 名前付き関数は **呼び出し時に** 読み取ります。

## 配列

```zymbol
配列 = [1, 2, 3, 4, 5]
>> 配列[1] ¶       // → 1   インデックスは1始まり
>> 配列[-1] ¶      // → 5   負の値は末尾からカウント
>> 配列$# ¶        // → 5   長さ
```

```zymbol
配列 = [1, 2, 3]
>> (配列$+ 6) ¶          // → [1, 2, 3, 6]   追加
>> (配列$+[2] 99) ¶      // → [1, 99, 2, 3]  位置2に挿入
>> (配列$- 3) ¶          // → [1, 2]         最初の出現を削除
>> (配列$-[1]) ¶         // → [2, 3]         インデックス1を削除
>> (配列$[1..2]) ¶       // → [1, 2]         スライス、両端を含む
>> (配列$? 3) ¶          // → #1             含む
```

これらはすべて `$` で始まります。これは **コレクション** の記号であり、その中で何が行われるかを示す記号が続きます: `#` いくつ、`+` 追加、`-` 削除、`?` 存在するか尋ねる。そして `??` と同様に、記号を2倍にすることはそれを徹底的に行うことを意味します: `$?` は値が *存在するか* を尋ね、`$??` は *いくつの場所に* 存在するかを尋ねてすべて返します。

```zymbol
配列 = [3, 1, 2]
>> (配列$^+) ¶     // → [1, 2, 3]   昇順
>> (配列$^-) ¶     // → [3, 2, 1]   降順
```

**結果のルール。** 1つのオペレーターと、周囲のコードがそれを使って何をするかが決定します: 使用されれば、**構築** して元のものをそのままにします; 破棄されれば、**変更** します。

```zymbol
配列 = [1, 2, 3]
コピー = 配列[2]$~ 99
>> 配列 ¶                // → [1, 2, 3]
>> コピー ¶              // → [1, 99, 3]
配列[2]$~ 99
>> 配列 ¶                // → [1, 99, 3]
```

> **`=` は決してコレクションに書き込みません。** `配列[2] = 99` は Zymbol の形式ではありません — `=` は **名前** に値を与えます。コレクションの一部を変更するのは `$~` であり、すべてのコレクションで同様です。

`[…]` は単一の型を含み検査されます; 意図的な混合は `#[…]` で **宣言** されます:

```zymbol
混合 = #[1, "二", #1]
>> 混合 ¶             // → [1, 二, #1]
>> ([1, 2] == #[1, 2]) ¶ // → #1
```

## 多次元インデックス

`>` はネストされた構造を下っていきます。1組の角括弧が1つの要素をアドレス指定します。どんなに深くても。

```zymbol
m = [[1,2,3], [4,5,6], [7,8,9]]
>> m[2>3] ¶        // → 6   行2、列3
>> m[-1>-1] ¶      // → 9   最終行、最終列
```

```zymbol
m = [[1,2,3], [4,5,6], [7,8,9]]
>> m[1>1 ; 2>2 ; 3>3] ¶          // → [1, 5, 9]         フラット: 対角線
>> m[[1>1, 1>3] ; [3>1, 3>3]] ¶  // → [[1, 3], [7, 9]]  構造化: 四隅
```

```zymbol
m = [[1,2,3], [4,5,6]]
>> (m[1>2]$~ 99) ¶      // → [[1, 99, 3], [4, 5, 6]]
```

> `m[1][2]` は Zymbol の形式 **ではありません**。チェーンインデックスは読み取りと書き込みの両方で拒否されます — アクセスごとに1組の角括弧、そして `>` がステップ間に入ります。

## 辞書

名前付きフィールドを持つタプルは辞書であり、v0.0.9 以降は `#(…)` と記述されます。

```zymbol
人物 = #(名前: "田中", 年齢: 25)
>> 人物.名前 ¶        // → 田中
>> 人物["年齢"] ¶    // → 25
```

```zymbol
人物 = #(名前: "田中", 年齢: 25)
フィールド = "名前"
>> 人物[フィールド] ¶     // → 田中
```

変更可能で、キーを追加でき、走査できます:

```zymbol
在庫 = #(ナシ: 4)
在庫["リンゴ"]$~ 10
@ k:在庫 { >> k "=" 在庫[k] " " }
>> ¶                    // → ナシ=4 リンゴ=10
```

```zymbol
在庫 = #(ナシ: 4, リンゴ: 10)
@ (k, v):在庫 { >> k ":" v " " }
>> ¶                    // → ナシ:4 リンゴ:10
```

> `#()` は空の辞書であり、`()` はそうではありませんでした — それは空のタプルでもある必要がありました。裸の `(甲: 1)` はこのメッセージとともに拒否されます: *a dictionary is written `#(…)`* — 「辞書は `#(…)` と書きます」。
> 辞書はキーでアドレス指定され、位置では決してアドレス指定されないため、`人物[1]` はエラーです。

## タプル

タプルは **不変** の順序付きコンテナであり、異なる型の値を保持できます。

```zymbol
点 = (10, 20)
>> 点[1] ¶           // → 10
データ = (42, "こんにちは", #1, 3.14)
>> データ[3] ¶            // → #1
```

```zymbol
t = (10, 20, 30)
t2 = t[2]$~ 999
>> t ¶                  // → (10, 20, 30)
>> t2 ¶                 // → (10, 999, 30)
```

> タプルをその場で変更しようとする試みはすべてエラーであり、オペレーターが何であれ — 不変性は値のプロパティであり、各 `$` 内の例外ではありません。

## 分解

```zymbol
配列 = [10, 20, 30, 40, 50]
[甲, 乙, 丙] = 配列
>> 甲 " " 乙 " " 丙 ¶      // → 10 20 [30, 40, 50]
```

```zymbol
配列 = [10, 20, 30, 40, 50]
[最初, *残り] = 配列
>> 最初 ¶            // → 10
>> 残り ¶              // → [20, 30, 40, 50]
```

```zymbol
点 = (100, 200)
(横, 縦) = 点
>> 横 " " 縦 ¶          // → 100 200
```

```zymbol
人物 = #(名前: "佐藤", 年齢: 25)
#(名前: n, 年齢: a) = 人物
>> n " " a ¶            // → 佐藤 25
```

> 括弧の形状は型付けされています: `[…]` は配列を、`(…)` はタプルを、`#(…)` は辞書を取ります。最後の名前は **残りを吸収** するため、分解は長さによって失敗することはありません — `(甲, 乙, 丙) = (1,2,3,4,5)` は `丙 = (3,4,5)` を与え、何も残っていない場合は `##_` となります。

## 高階関数

```zymbol
数値 = [1, 2, 3, 4, 5]
>> (数値$> (甲 -> 甲 * 2)) ¶ // → [2, 4, 6, 8, 10]
>> (数値$| (甲 -> 甲 % 2 == 0)) ¶ // → [2, 4]
>> (数値$< (0, (累積, 甲) -> 累積 + 甲)) ¶ // → 15
```

```zymbol
数値 = [1, 2, 3, 4, 5, 6]
二倍(甲) { <~ 甲 * 2 }
大きい(甲) { <~ 甲 > 3 }
>> (数値$> 二倍) ¶    // → [2, 4, 6, 8, 10, 12]
>> (数値$| 大きい) ¶    // → [4, 5, 6]
```

```zymbol
データベース = [#(名前: "カルラ", 年齢: 28), #(名前: "佐藤", 年齢: 25)]
年齢順 = データベース$^ (甲, 乙 -> 甲.年齢 < 乙.年齢)
>> 年齢順[1].名前 ¶     // → 佐藤
```

> 名前付き関数は HOF に **括弧なし** で渡されます: `数値$> 二倍`。`数値$> (二倍)` と書くのは構文解析エラーです。なぜなら `(` はラムダを開くからです。

## エラー処理

```zymbol
!? {
    甲 = 10 / 0
} :! ##Div {
    >> "ゼロ除算" ¶  // → ゼロ除算
} :! {
    >> "その他: " _err ¶
} :> {
    >> "常に実行" ¶        // → 常に実行
}
```

| 種類 | 発生時 |
|------|--------|
| `##Div` | ゼロ除算 |
| `##Index` | インデックスが範囲外 |
| `##Key` | 辞書にキーがない |
| `##Range` | 安全な整数範囲外 |
| `##Type` | 型の不一致 |
| `##Parse` | データ解析 |
| `##IO` | ファイル / システム |
| `##Network` | ネットワークエラー |
| `##DB` | データベース |
| `##Time` | 存在しない日付 |
| `##_` | 任意のエラー（全捕捉） |

`!` は **エラーと強制** の記号であり、両方のファミリーで同じように読み取られます: `$!` は値にエラーかどうかを尋ねます; `$!!` は記号を2倍にして、尋ねずに上位に伝播させます。

> 標準ライブラリの失敗は、アボートする代わりに、`$!` でテストするか `!?` で捕捉する **ソフトエラー値** として返されます。`$!!` は呼び出し元に伝播させます。

## モジュール

```zymbol
# 電卓 {
    #> { 加算, PI }

    PI := 3.14159
    加算(甲, 乙) { <~ 甲 + 乙 }
}
```

```zymbol
<# ./電卓 => c

>> c::加算(5, 3) ¶
>> c.PI ¶
```

```zymbol
# 私のライブラリ {
    #> { 内部加算 => 和 }

    内部加算(甲, 乙) { <~ 甲 + 乙 }
}
```

2つのモジュール記号は同じ考えであり、今度はファイルに適用されます: `#` は **宣言** のレベルです — 物事が *何であるか*、その価値ではなく — 矢印はコードがどの方向に移動するかを示します:

```text
<#   矢印が入る: インポート、別のファイルから持ってくる
#>   矢印が出る: エクスポート、他のファイルに提供する
```

方向記号は常に、指す方向を向いた端に位置します。これは `<~` が左に戻る（関数の外へ）理由や、`->` が右に入る（ラムダの本体へ）理由と同じです。

> **モジュールはエクスポートするものを宣言します。** `#>` ブロックは必須です — 省略すると **E014** であり、`#> { }` はモジュールがその表面が空であることを示す方法です。`::` は関数を呼び出し、`.` は定数を読み取ります。モジュール本体に現れることができるのは、インポート、エクスポートブロック、リテラル初期化子、関数定義のみです; 実行可能なものはすべて **E013** です。

```zymbol
<# std/math => m

>> m::sqrt(16.0) ¶      // → 4
>> m.PI ¶               // → 3.141592653589793
```

```zymbol
<# std/term => t
```

## 数字モード

Zymbol は **69 の Unicode 数字体系** で数値を書くことができます — デーヴァナーガリー、アラビア・インド数字、タイ数字、クリンゴン語 pIqaD、数学的太字、LCDセグメントなど。モードはプロセス全体にグローバルであり、出力に影響します; 算術は変更されません。

```zymbol
#０９#    // 全角数字 (U+FF10–U+FF19)
#०९#    // デーヴァナーガリー   (U+0966–U+096F)
#٠٩#    // アラビア・インド (U+0660–U+0669)
#09#    // ASCII にリセット
```

```zymbol
甲 = 42
>> 甲 ¶                  // → 42
#０９#
>> 甲 ¶                  // → ４２
>> 3.14 ¶               // → ３.１４
>> #1 ¶                 // → #１
#09#
```

サポートされている任意の文字体系の数字は、ソース内で有効なリテラルです:

```zymbol
#０９#
@ i:１..５ { >> i " " }
>> ¶                    // → １ ２ ３ ４ ５
#09#
```

読み取りは対称的です — 数字は任意の文字体系で理解されます:

```zymbol
>> #|"４２"| ¶            // → 42
>> #|'７'| ¶             // → 7
```

> `#` は常に ASCII であるため、`#0` はどの文字体系でも数字のゼロと視覚的に区別されます。
> `#,` と `#^` もアクティブな文字体系で数字を書き、区切り文字もそれに従います — しかしペアが反転することはありません: `,` はグループ化し、`.` は区切り、すべての文字体系で同様です。

## データオペレーター

```zymbol
f = ##.42         // 浮動小数へ
i = ###3.7        // 整数へ、四捨五入  → 4
t = ##!3.7        // 整数へ、切り捨て  → 3
>> f " " i " " t ¶      // → 42 4 3
>> f#? ¶                // → (##., 2, 42)
```

> 浮動小数は数字として出力され、指数表記にはならず、末尾の `.0` は削除されます — `##.42` は `42` と出力され、それでも浮動小数です。`f#?` が示す通りです。

```zymbol
>> #|"42"| ¶       // → 42
>> #|"abc"| ¶      // → abc   フェイルセーフ: 入力をそのまま返す
>> ##!'A' ¶        // → 65    文字のコードポイント
```

```zymbol
円周率 = 3.14159265
>> #.2|円周率| ¶       // → 3.14          小数第2位で四捨五入
>> #!2|円周率| ¶       // → 3.14          小数第2位で切り捨て
>> #,|1234567| ¶   // → 1,234,567     千単位の区切り
>> #^|12345.678| ¶ // → 1.2345678e4   指数表記
```

```zymbol
>> 0x41 ¶        // → A   16進数
>> 0b01000001 ¶  // → A   2進数
>> 0o101 ¶       // → A   8進数
>> 0d65 ¶        // → A   10進数
```

> ASCII 範囲の基数リテラルは **文字** です: `0d65 == 'A'` は `#1` であり、`0d65 == 65` は `#0` です。4つの基数はすべて同じ文字を表します。

## 記号の組み合わせ方

このマニュアル全体を通して同じことを見てきました: **オペレーターは覚えるための図ではなく、連続した複数の記号であり、それぞれが意味を提供します。** 今やそれらすべてを知ったので、完全なパターンは次のとおりです。

まず **どの世界にいるか** が来ます:

| 記号 | 世界 | 登場箇所 |
|------|------|----------|
| `$` | コレクション | `$#` `$+` `$?` `$^-` |
| `@` | 時間、繰り返されるもの | `@!` `@>` `@~` |
| `#` | 何かが *何であるか*、その価値ではない | `#?` `#(…)` `<#` `#>` |
| `>>` | プログラムから外へ | `>>` `>>!` `>>?` |
| `<<` | プログラムの中へ | `<<` `<<\|` `<<\|?` |
| `?` | 尋ねる、コミットせずに | `?` `_?` `??` `$?` |
| `!` | 強制、またはエラー | `@!` `$!` `!?` |

次に **そこで何が行われるか** が来ます: `+` 追加、`-` 削除、`^` 順序付け、`~` 変更、`#` カウント、`|` 単一ユニット、`:` 名前の束縛。

そして決して失敗しない2つのルール:

**記号を2倍にすると徹底的になります。** `?` は1回尋ね、`??` は多くのケースをテストします。`$?` は値が存在するか尋ね、`$??` は存在するすべての場所を返します。`!` はエラーをマークし、`!!` は尋ねずに伝播させます。

**モード記号は常に最後に来ます。** `?` または `!` が何かが *どのように* 行われるか — ためらいながらか強制的に — を言うために現れるとき、それらはオペレーターの最後の記号です: `$??`、`$!!`、`<<|?`、`@!`、`##!`、`>>!`、`>>?`、`@:外部!`。それらの後に操作が続くことはありません。

そこから実用的なことが導かれます: **一度も見たことがない組み合わせでも、調べる前にすでに意味がわかります。** `$` がコレクションで `^` が順序で `-` が逆なら、`$^-` は降順にソートし、誰も教える必要はありませんでした。

すべての在庫がこのように機能するわけではなく、そう言うことは偽るより良いです。ほとんどのオペレーターはきれいに分解できます。6つは分解できますが、部分よりも多くを意味します: `!?` `:!` `:>` `|>` `::` `$++`。そして10個はまったく分解できないため、暗記する必要があります: `¶` `><` `#1` `#0` `0x` `0b` `0o` `0d` `###` `°`。

> 不透明なものを数えることは、それらが少ないと仮定するよりも意図的です: それらは言語の実際の記憶コストです。完全なリファレンス — 在庫、宣言された同形異義語、新しいオペレーターが存在するために満たすべきルール — はインタープリターリポジトリの `SYMBOLS.md` にあります。

## リリース変更履歴

### v0.0.9 — コレクションの決定 _(2026年9月)_

- **互換性破壊** 辞書に独自の表記法が追加されました: `#(キー: 値)`。裸の `(甲: 1)` は拒否され、`#()` が空の辞書になりました — `()` にはなり得ませんでした
- **互換性破壊** インデックス代入が廃止されました: `配列[i] = v` およびすべての複合形式。`=` は **名前** に値を与えます; コレクションの一部を変更するのは `$~` です
- **互換性破壊** チェーンインデックス `m[i][j]` は読み取りと書き込みの両方で拒否されます — `>` がステップ間に入ります
- **互換性破壊** モジュールはエクスポートするものを宣言しなければなりません（**E014**）; `#> { }` はモジュールが表面が空であることを示す方法です
- **互換性破壊** ループ指定子はカウントまたは条件です — 真理値はありません。`@ []` と `@ 3.5` は拒否されます
- **追加** `##_` — ユニットリテラル、およびプログラムが何かが存在しないかどうかを尋ねる方法
- **追加** `#[…]` — 要素型の混合が宣言された配列
- **追加** `#?` が4つのコレクションを区別します: `##]` `##[` `##)` `##(`
- **追加** `std/time` — 時計と市民暦、タイムゾーンと暦演算付き
- **追加** トップレベルの `<~>` はプログラムの終了ステータスです
- **追加** `@ (k, v):ペア` — ループヘッダのパターン
- **追加** `#|c|` が69の文字体系のいずれかの数字を読み取ります; `#,` と `#^` はアクティブな文字体系で数字を書きます
- **変更** `整数` は安全な整数、±(2⁵³ − 1)、すべてのエンジンでフェイルクローズ
- **変更** 名前付き関数は呼び出し時にファイルの変数を値で読み取ります
- **変更** 名前だけを読み取る文は黙って通過する代わりに警告を発します
- **エンジン** 666のコーパスファイル中660が3つのエンジンすべてで合意、0件の相違
