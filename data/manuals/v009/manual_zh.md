# Zymbol-Lang 手册

> **针对 v0.0.9 修订 — 2026-09-07**

**Zymbol-Lang** 是一种符号化编程语言。其语法中不含任何单词——每个结构都是一个符号。它在任何人类语言中都能以相同方式工作。

- 没有 `if`、`while`、`return` —— 只有 `?`、`@`、`<~`
- 完全支持 Unicode —— 标识符可使用任何语言或表情符号
- 与人类语言无关 —— 代码在任何地方都是相同的

**解释器版本**：v0.0.9 | **测试覆盖率**：660/666（三个引擎达成一致，0 个分歧）

## 变量与常量

```zymbol
甲 = 10              // 可变变量
PI := 3.14159       // 常量 — 重新赋值会导致运行时错误
姓名 = "王芳"
活跃 = #1           // 布尔真值
👋 := "你好"
```

```zymbol
甲 = 10    // 10
甲 += 5    // 15
甲 -= 3    // 12
甲 *= 2    // 24
甲 /= 3    // 8
甲 %= 3    // 2
甲 ^= 2    // 4
甲++       // 5
甲--       // 4
```

`°`（度数符号，U+00B0）在首次使用时将变量自动初始化为其中性值：

```zymbol
数字列表 = [3, 1, 4, 1, 5]
@ 数:数字列表 {
    °累计 += 数
}
>> 累计 ¶              // → 14
```

> `°变量`（前缀）锚定在循环之上 — 结果在 `@` 之后可读。
> `变量°`（后缀）锚定在循环内部 — 它在循环结束时消亡。

仅由一个名称组成的语句会读取变量并丢弃该值，因此编译器会发出警告：

```zymbol
计数 = 5
计数
```

编译器会这样警告（其消息始终为英文）：

```text
warning: this statement does nothing: '计数' is read and discarded
  = help: remove it, or use it — `>> name ¶` to print it
```

意思是：*「此语句不执行任何操作：读取了 '计数' 并将其丢弃」*。

## 数据类型

| 类型 | 字面量 | `#?` 标签 | 备注 |
|------|---------|-----------|------|
| 整数 | `42`, `-7` | `###` | 安全整数：±(2⁵³ − 1) |
| 浮点数 | `3.14`, `1.5e10` | `##.` | IEEE-754 双精度 |
| 字符串 | `"文本"` | `##"` | 插值：`"你好 {姓名}"` |
| 字符 | `'A'` | `##'` | 一个 Unicode 字素 |
| 布尔值 | `#1`, `#0` | `##?` | 不是数字 — `#1 ≠ 1` |
| 数组 | `[1, 2, 3]` | `##]` | 单一类型，已检查 |
| 声明的混合数组 | `#[1, "二"]` | `##[` | 与 `[…]` 类型相同，不检查 |
| 元组 | `(甲, 乙)` | `##)` | 位置型，不可变 |
| 字典 | `#(甲: 1, 乙: 2)` | `##(` | 键值型，可变 |
| 函数 | 命名函数引用 | `##()` | 一等公民；显示为 `<funct/N>` |
| Lambda | `甲 -> 甲 * 2` | `##->` | 一等公民；显示为 `<lambd/N>` |
| 单元 | `##_` | `##_` | 不存在 — 没有 null |

```zymbol
>> 42#? ¶               // → (###, 2, 42)
>> [1, 2, 3]#? ¶        // → (##], 3, [1, 2, 3])
>> #(甲: 1)#? ¶          // → (##(, 1, #(甲: 1))
```

超出安全范围的整数是一个可捕获的错误，永远不会静默环绕：

```zymbol
!? {
    >> (9007199254740991 + 1) ¶
} :! ##Range {
    >> "超出范围" ¶ // → 超出范围
}
```

`##_` 是程序询问某物是否不存在的方式：

```zymbol
空() { }
值 = 空()
>> (值 == ##_) ¶     // → #1
```

## 输出与输入

```zymbol
姓名 = "王芳"
总计 = 3
>> "你好" ¶             // → 你好
>> "姓名=" 姓名 " 总计=" 总计 ¶ // → 姓名=王芳 总计=3
>> 总计#? ¶            // → (###, 1, 3)
```

```zymbol
<< 姓名
<< "请输入您的名字：" 姓名
<< ###(4) "年龄：" 年龄
```

**注意这两个符号的形状。** `>>` 指向外部：它将数据从程序中取出。`<<` 指向内部：它将数据带入程序。这里没有任何需要记忆的内容 — 箭头指明了信息的流向，并且同样的理念在每一个移动数据的符号中都会重现。

> `¶` 和 `\\` 是等效的换行符。`>>` 从不自动添加换行符。
> 提示符前的类型说明符会在读取时进行验证，并在有效之前重复提示：
> `##.` 浮点数 · `##.(T,D)` 小数 · `###(N)` 整数 · `##"(N)` 文本 · `##'` 单个字符。

在文件的顶层，`<~` 是程序的退出状态：

```zymbol
>> "正在检查" ¶      // → 正在检查
<~ 0
```

## TUI 原语

用于交互式程序的终端 UI 操作符。大多数需要 `>>| { }` 块（备用屏幕 + 原始模式）。

```zymbol
>>| {
    >>!
    >>~ (1, 1, 0, 10) > "正在运行"
    @~ 1000
    >>~ (2, 1) > "完成。"
}
```

```zymbol
>>| {
    [行数, 列数] = >>?
    >>~ (1, 1) > "终端：" 行数 " x " 列数
    <<| 按键
    >>~ (2, 1) > "按下了：" 按键
}
```

这就是为什么符号是组合而非倍增的原因。你已经知道 `<<` 是输入，`?` 是询问而不承诺。只有一个新符号：

- `|` 是 **单个单元**，而不是整个流。

这样，两个键盘操作符就一目了然了：

```text
<<        |             ?
输入      单个单元      不承诺

<<|   取一个按键，并等待直到有按键
<<|?  查看是否有一个按键，如果没有则继续
```

另一边也是如此：`>>` 输出，`>>!` **强制**输出（清除整个屏幕），而 `>>?` 则 **询问** 而非写入（终端有多大）。右边的符号是改变模式的符号，它总是放在最后。

> `>>!` 清除屏幕。`>>?` 返回 `(行数, 列数)`。`@~ N` 休眠 N 毫秒。
> `<<|` 读取一次按键（阻塞）；`<<|?` 轮询而不阻塞（如果没有则为 `'\0'`）。
> 方向键解码为 `'↑' '↓' '←' '→'`；ESC 是码点 27。
> 定位输出元组：`(行, 列, BKS, 前景, 背景)` — 任何槽位都可以用逗号省略（`>>~ (,,, 196) > "红色"`）。
> BKS 位掩码：`1`=粗体，`2`=斜体，`4`=下划线。ANSI 256 色调色板（`0`=终端默认）。

## 运算符

```zymbol
甲 = 10
乙 = 3
结果1 = 甲 + 乙    // 13
结果2 = 甲 - 乙    // 7
结果3 = 甲 * 乙    // 30
结果4 = 甲 / 乙    // 3  (整数除法)
结果5 = 甲 % 乙    // 1
结果6 = 甲 ^ 乙    // 1000
```

```zymbol
甲 = 10
乙 = 3
比较1 = 甲 == 乙    // #0
比较2 = 甲 <> 乙    // #1
比较3 = 甲 < 乙     // #0
比较4 = 甲 >= 乙    // #1
逻辑1 = #1 && #0  // #0
逻辑2 = !#1       // #0
```

> `==` 从不进行强制转换：`"5" == 5` 是 `#0`。排序比较会进行转换：`"5" > 4` 是 `#1`，并且 `"४२" > 5` 也是 — 在 69 种数字文字中的任意一种中，数字文本都会作为数字进行比较。
> 一个函数只等于它自己，永远不等于另一个具有相同主体的函数。

## 字符串

```zymbol
姓名 = "王芳"
数 = 42
>> "你好 " 姓名 " 你有 " 数 ¶ // → 你好 王芳 你有 42
描述 = "你好 {姓名}，你有 {数}"
>> 描述 ¶              // → 你好 王芳，你有 42
```

```zymbol
串 = "苹果,香蕉,橙子"
长度 = 串$#                  // 7
子串 = 串$[1..2]             // "苹果"
包含 = 串$? "香蕉"          // #1
部分 = "苹果,香蕉,橙子"$/ ','   // [苹果, 香蕉, 橙子]
替换 = 串$~~["苹":"柠"]     // "柠檬,香蕉,橙子"
线条 = "─" $* 20
```

> `+` 只用于数字。字符串请使用并列或插值。
> `\{` 和 `\}` 是字面大括号 — 转义是对称的。

## 控制流

```zymbol
甲 = 7
? 甲 > 100 {
    >> "大" ¶
} _? 甲 > 0 {
    >> "正数" ¶     // → 正数
} _ {
    >> "负数" ¶
}
```

这里有两个新符号，第三个是它们组合而成的：

- `?` 是 **询问**：它开启一个条件。
- `_` 是 **未指定的情况**：当没有任何问题匹配时留下的分支。
- `_?` 是两者连续：*如果什么都没匹配，再问一次*。

这就是 `_?` 这样写的原因。它不是一个需要学习的新符号 — 它是 `_` 后面跟着 `?`，它的意思正是它的两个部分按顺序读起来的意思。

> `{ }` 大括号即使是单条语句也 **必须** 使用。

## 匹配

```zymbol
分数 = 85
等级 = ?? 分数 {
    90..100 => '优'
    80..89  => '良'
    _       => '差'
}
>> 等级 ¶              // → 良
```

```zymbol
温度 = -5
状态 = ?? 温度 {
    < 0  => "冰"
    < 20 => "冷"
    _    => "热"
}
>> 状态 ¶              // → 冰
```

你已经知道 `?` 是“询问”。**`??` 是多次询问**：在语言中任何地方重复一个符号，就是多次执行该符号所做的事情。一个 `?` 测试一个条件；`??` 测试一系列情况。

备选项用 `||` 连接，它们可以混合模式种类：

```zymbol
键 = 'P'
动作 = ?? 键 {
    'p' || 'P' => "暂停"
    < 0 || > 100 => "超出范围"
    _ => "忽略"
}
>> 动作 ¶             // → 暂停
```

## 循环

```zymbol
@ 计:1..4  { >> 计 " " }
>> ¶                    // → 1 2 3 4
@ 计:1..9:2 { >> 计 " " }
>> ¶                    // → 1 3 5 7 9
@ 计:5..1:1 { >> 计 " " }
>> ¶                    // → 5 4 3 2 1
```

```zymbol
数 = 1
@ 数 <= 64 { 数 *= 2 }
>> 数 ¶                  // → 128
```

```zymbol
水果 = ["苹果", "香蕉", "橙子"]
@ 果:水果 { >> 果 " " }
>> ¶                    // → 苹果 香蕉 橙子
@ 字:"你好" { >> 字 "-" }
>> ¶                    // → 你-好-
```

```zymbol
@ 计:1..10 {
    ? 计 % 2 == 0 { @> }
    ? 计 > 7 { @! }
    >> 计 " "
}
>> ¶                    // → 1 3 5 7
```

```zymbol
计数 = 0
@:外部 {
    计数++
    ? 计数 >= 3 { @:外部! }
}
>> 计数 ¶             // → 3
```

`@` 是 **时间** 的符号：所有重复的事物都存在于其中。要缩短这个时间，你可以在它旁边添加一个符号：

- `@!` — `!` 是 **强制**：立即离开循环。
- `@>` — `>` 向前推进：跳到下一轮。
- `@:外部!` — `:` **绑定一个名称**，因此这会切断名为 *外部* 的循环，而不是最近的循环。

三个操作符，没有一个是需要单独记忆的：它们是 `@` 加上一个已经说明其含义的符号。

> **说明符是一个计数或一个条件。** `整数` 是一个计数，只计算一次 — `@ 0` 执行零次循环体。其他任何东西都是一个条件。没有真值性：`@ []` 和 `@ 3.5` 会被拒绝。要遍历集合使用 `@ 项:集合`；要计数使用 `@ 集合$#`。

## 函数

```zymbol
加(甲, 乙) { <~ 甲 + 乙 }
>> 加(3, 4) ¶        // → 7
```

```zymbol
阶乘(数) {
    ? 数 <= 1 { <~ 1 }
    <~ 数 * 阶乘(数 - 1)
}
>> 阶乘(5) ¶       // → 120
```

函数按值读取文件中的变量，内部的写入只停留在内部：

```zymbol
限制 = 100
在范围内(数) { <~ 数 < 限制 }
>> 在范围内(42) ¶         // → #1
```

两个符号可以改变这一点，并且它们都 **在签名和调用处** 书写：

```zymbol
递增(计数器<~) { 计数器 = 计数器 + 1 }
总计 = 0
递增(总计<~)
>> 总计 ¶              // → 1
```

> `参数~` 是一个工作副本 — 函数体可以重新赋值它，而调用者不受影响。
> `参数<~` 是一个输出参数 — 更改会传回。没有符号的 `递增(总计)` 是一个语义错误：注解和签名不能分离。

## Lambda 与闭包

```zymbol
双倍 = 甲 -> 甲 * 2
和 = (甲, 乙) -> 甲 + 乙
>> 双倍(5) ¶          // → 10
>> 和(3, 7) ¶          // → 10
```

```zymbol
分类 = 甲 -> {
    ? 甲 > 0 { <~ "正数" }
    _? 甲 < 0 { <~ "负数" }
    <~ "零"
}
>> 分类(-4) ¶         // → 负数
```

```zymbol
因子 = 3
三倍 = 甲 -> 甲 * 因子
>> 三倍(7) ¶          // → 21
```

```zymbol
创建加法器(数) { <~ 甲 -> 甲 + 数 }
加10 = 创建加法器(10)
>> 加10(5) ¶           // → 15
```

Lambda 可以不接受任何参数：

```zymbol
答案 = () -> 42
>> 答案() ¶           // → 42
```

> Lambda 在 **创建时** 捕获文件中的变量；命名函数在 **调用时** 读取它们。

## 数组

```zymbol
数组 = [1, 2, 3, 4, 5]
>> 数组[1] ¶       // → 1   索引从 1 开始
>> 数组[-1] ¶      // → 5   负数从末尾计数
>> 数组$# ¶        // → 5   长度
```

```zymbol
数组 = [1, 2, 3]
>> (数组$+ 6) ¶          // → [1, 2, 3, 6]   追加
>> (数组$+[2] 99) ¶      // → [1, 99, 2, 3]  在位置 2 插入
>> (数组$- 3) ¶          // → [1, 2]         移除首次出现的值
>> (数组$-[1]) ¶         // → [2, 3]         移除索引 1 处的值
>> (数组$[1..2]) ¶       // → [1, 2]         切片，包含两端
>> (数组$? 3) ¶          // → #1             是否包含
```

它们都以 `$` 开头，这是 **集合** 的符号，后面跟着一个说明对其执行什么操作的符号：`#` 多少个，`+` 添加，`-` 移除，`?` 询问是否存在。与 `??` 一样，重复符号意味着穷举执行：`$?` 询问 *是否* 存在某个值，`$??` 询问 *在多少个位置* 存在并全部返回。

```zymbol
数组 = [3, 1, 2]
>> (数组$^+) ¶     // → [1, 2, 3]   升序
>> (数组$^-) ¶     // → [3, 2, 1]   降序
```

**结果的规则。** 一个操作符，周围代码如何处理它决定了结果：如果使用了结果，则 **构建** 并保持原样；如果丢弃了结果，则 **修改**。

```zymbol
数组 = [1, 2, 3]
副本 = 数组[2]$~ 99
>> 数组 ¶                // → [1, 2, 3]
>> 副本 ¶              // → [1, 99, 3]
数组[2]$~ 99
>> 数组 ¶                // → [1, 99, 3]
```

> **`=` 从不写入集合。** `数组[2] = 99` 不是 Zymbol 的合法形式 — `=` 将值赋给一个名称。更改集合的一部分是 `$~`，在所有集合中都是如此。

`[…]` 包含单一类型并进行检查；有意的混合类型使用 `#[…]` **声明**：

```zymbol
混合 = #[1, "二", #1]
>> 混合 ¶             // → [1, 二, #1]
>> ([1, 2] == #[1, 2]) ¶ // → #1
```

## 多维索引

`>` 向下遍历嵌套结构。一组方括号寻址一个元素，无论多深。

```zymbol
矩阵 = [[1,2,3], [4,5,6], [7,8,9]]
>> 矩阵[2>3] ¶        // → 6   第 2 行，第 3 列
>> 矩阵[-1>-1] ¶      // → 9   最后一行，最后一列
```

```zymbol
矩阵 = [[1,2,3], [4,5,6], [7,8,9]]
>> 矩阵[1>1 ; 2>2 ; 3>3] ¶          // → [1, 5, 9]         扁平：对角线
>> 矩阵[[1>1, 1>3] ; [3>1, 3>3]] ¶  // → [[1, 3], [7, 9]]  结构化：角点
```

```zymbol
矩阵 = [[1,2,3], [4,5,6]]
>> (矩阵[1>2]$~ 99) ¶      // → [[1, 99, 3], [4, 5, 6]]
```

> `矩阵[1][2]` **不是** Zymbol 的合法形式。链式索引无论是读取还是写入都被拒绝 — 每次访问一组方括号，`>` 放在步骤之间。

## 字典

带有命名字段的元组是一个字典，从 v0.0.9 开始写作 `#(…)`。

```zymbol
人员 = #(姓名: "王芳", 年龄: 25)
>> 人员.姓名 ¶        // → 王芳
>> 人员["年龄"] ¶    // → 25
```

```zymbol
人员 = #(姓名: "王芳", 年龄: 25)
字段 = "姓名"
>> 人员[字段] ¶     // → 王芳
```

它是可变的，可以添加键，并且可以遍历：

```zymbol
库存 = #(香蕉: 4)
库存["苹果"]$~ 10
@ 键:库存 { >> 键 "=" 库存[键] " " }
>> ¶                    // → 香蕉=4 苹果=10
```

```zymbol
库存 = #(香蕉: 4, 苹果: 10)
@ (键, 值):库存 { >> 键 ":" 值 " " }
>> ¶                    // → 香蕉:4 苹果:10
```

> `#()` 是空字典，这是 `()` 无法做到的 — 它必须同时也是空元组。裸的 `(甲: 1)` 会被拒绝，并显示消息 *a dictionary is written `#(…)`* — 「字典写作 `#(…)`」。
> 字典通过键来寻址，从不通过位置，因此 `人员[1]` 是一个错误。

## 元组

元组是 **不可变的** 有序容器，可以保存不同类型的值。

```zymbol
点 = (10, 20)
>> 点[1] ¶           // → 10
数据 = (42, "你好", #1, 3.14)
>> 数据[3] ¶            // → #1
```

```zymbol
元 = (10, 20, 30)
元2 = 元[2]$~ 999
>> 元 ¶                  // → (10, 20, 30)
>> 元2 ¶                 // → (10, 999, 30)
```

> 任何试图就地修改元组的操作都是一个错误，无论操作符是什么 — 不可变性是值的一个属性，而不是每个 `$` 内部的例外。

## 解构

```zymbol
数组 = [10, 20, 30, 40, 50]
[甲, 乙, 丙] = 数组
>> 甲 " " 乙 " " 丙 ¶      // → 10 20 [30, 40, 50]
```

```zymbol
数组 = [10, 20, 30, 40, 50]
[第一个, *剩余] = 数组
>> 第一个 ¶            // → 10
>> 剩余 ¶              // → [20, 30, 40, 50]
```

```zymbol
点 = (100, 200)
(横, 纵) = 点
>> 横 " " 纵 ¶          // → 100 200
```

```zymbol
人员 = #(姓名: "李明", 年龄: 25)
#(姓名: 名, 年龄: 岁) = 人员
>> 名 " " 岁 ¶            // → 李明 25
```

> 括号的形状是类型化的：`[…]` 接受数组，`(…)` 接受元组，`#(…)` 接受字典。最后一个名称 **吸收剩余部分**，因此解构永远不会因长度而失败 — `(甲, 乙, 丙) = (1,2,3,4,5)` 得到 `丙 = (3,4,5)`，当没有剩余时得到 `##_`。

## 高阶函数

```zymbol
数字列表 = [1, 2, 3, 4, 5]
>> (数字列表$> (甲 -> 甲 * 2)) ¶ // → [2, 4, 6, 8, 10]
>> (数字列表$| (甲 -> 甲 % 2 == 0)) ¶ // → [2, 4]
>> (数字列表$< (0, (累计, 甲) -> 累计 + 甲)) ¶ // → 15
```

```zymbol
数字列表 = [1, 2, 3, 4, 5, 6]
双倍(甲) { <~ 甲 * 2 }
是大(甲) { <~ 甲 > 3 }
>> (数字列表$> 双倍) ¶    // → [2, 4, 6, 8, 10, 12]
>> (数字列表$| 是大) ¶    // → [4, 5, 6]
```

```zymbol
数据库 = [#(姓名: "王芳", 年龄: 28), #(姓名: "李明", 年龄: 25)]
按年龄排序 = 数据库$^ (甲, 乙 -> 甲.年龄 < 乙.年龄)
>> 按年龄排序[1].姓名 ¶ // → 李明
```

> 命名函数传递给高阶函数时 **不带括号**：`数字列表$> 双倍`。写成 `数字列表$> (双倍)` 是解析错误，因为 `(` 开始一个 lambda。

## 错误处理

```zymbol
!? {
    甲 = 10 / 0
} :! ##Div {
    >> "除以零" ¶  // → 除以零
} :! {
    >> "其他：" _err ¶
} :> {
    >> "始终运行" ¶        // → 始终运行
}
```

| 类型 | 何时发生 |
|------|---------|
| `##Div` | 除以零 |
| `##Index` | 索引超出范围 |
| `##Key` | 字典中缺少键 |
| `##Range` | 超出安全整数范围 |
| `##Type` | 类型不匹配 |
| `##Parse` | 数据解析 |
| `##IO` | 文件 / 系统 |
| `##Network` | 网络错误 |
| `##DB` | 数据库 |
| `##Time` | 不存在的日期 |
| `##_` | 任何错误（捕获所有） |

`!` 是 **错误和强制** 的符号，在两个系列中读法相同：`$!` 询问一个值是否是错误；`$!!`，符号重复，向上传播而不询问。

> 标准库失败返回的是 **软错误值**，你可以用 `$!` 测试或用 `!?` 捕获，而不是中止。`$!!` 将一个错误传播给调用者。

## 模块

```zymbol
# 计算器 {
    #> { 加, PI }

    PI := 3.14159
    加(甲, 乙) { <~ 甲 + 乙 }
}
```

```zymbol
<# ./计算器 => 计算

>> 计算::加(5, 3) ¶
>> 计算.PI ¶
```

```zymbol
# 我的库 {
    #> { 内部加 => 求和 }

    内部加(甲, 乙) { <~ 甲 + 乙 }
}
```

两个模块符号是同样的理念，现在应用于文件：`#` 是 **声明** 的层级 — 一个事物 *是什么*，而不是它的值 — 箭头表示代码的流向：

```text
<#   箭头进入：导入，从另一个文件带来
#>   箭头离开：导出，提供给其他文件
```

方向符号总是放在指向方向的边缘上。这与 `<~` 向左返回（离开函数）和 `->` 向右进入（进入 lambda 主体）的原因相同。

> **模块声明它导出的内容。** `#>` 块是必需的 — 省略它是 **E014**，而 `#> { }` 是模块表示其表面为空的方式。`::` 调用函数，`.` 读取常量。模块主体中只能出现导入、导出块、字面初始化器和函数定义；任何可执行内容都是 **E013**。

## 标准库

原生模块，像其他模块一样导入：

| 模块 | 函数 |
|------|------|
| `std/math` | `sqrt exp ln log pow abs ceil floor round min max sin cos tan` · `PI` `E` |

```zymbol
<# std/math => 数

>> 数::sqrt(16.0) ¶      // → 4
>> 数.PI ¶               // → 3.141592653589793
```

<# std/term => 终

>> 终::width("手番") ¶            // → 4   两个字形，四列

`.zyp` 将一个多文件程序打包成一个可移植文件。它是 **源代码** 的归档，而非二进制文件，因此可以在任何有 `zymbol` 二进制文件的地方运行。

```bash
zymbol package 我的项目/ --script main.zy -o 我的项目.zyp
zymbol run 我的项目.zyp
```

> 归档文件包含一个清单（`zyp.toml`），声明其入口脚本和所需的引擎版本。`zymbol run` 将其解压到临时目录并从那里运行，因此代码是一次性的，而脚本写入的内容会落在你的真实工作目录中。Playground 也可以加载 `.zyp` 文件。

## 数字模式

Zymbol 可以使用 **69 种 Unicode 数字文字** 书写数字 — 天城文、阿拉伯-印度文、泰文、克林贡语 pIqaD、数学粗体、LCD 段等。该模式对进程全局有效，影响输出；算术运算不变。

```zymbol
#०९#    // 天城文   (U+0966–U+096F)
#٠٩#    // 阿拉伯-印度文 (U+0660–U+0669)
#๐๙#    // 泰文         (U+0E50–U+0E59)
#09#    // 重置为 ASCII
```

```zymbol
甲 = 42
>> 甲 ¶                  // → 42
#०९#
>> 甲 ¶                  // → ४२
>> 3.14 ¶               // → ३.१४
>> #1 ¶                 // → #१
#09#
```

任何支持的文字中的数字在源代码中都是有效的字面量：

```zymbol
#०९#
@ 计:१..५ { >> 计 " " }
>> ¶                    // → १ २ ३ ४ ५
#09#
```

读取是对称的 — 任何文字中的数字都能被理解：

```zymbol
>> #|"४२"| ¶            // → 42
>> #|'७'| ¶             // → 7
```

> `#` 始终是 ASCII，因此 `#0` 在所有文字中都与数字零视觉上可区分。
> `#,` 和 `#^` 也使用当前活动文字书写其数字，分隔符也随之变化 — 但这对符号从不颠倒：`,` 分组，`.` 分隔，在所有文字中都是如此。

## 数据操作符

```zymbol
浮 = ##.42         // 转为浮点数
整 = ###3.7        // 转为整数，四舍五入  → 4
截 = ##!3.7        // 转为整数，截断    → 3
>> 浮 " " 整 " " 截 ¶      // → 42 4 3
>> 浮#? ¶                // → (##., 2, 42)
```

> 浮点数以数字打印，从不使用指数，并去掉末尾的 `.0` — `##.42` 打印 `42`，但它仍然是浮点数，正如 `浮#?` 所示。

```zymbol
>> #|"42"| ¶       // → 42
>> #|"abc"| ¶      // → abc   防故障：原样返回输入
>> ##!'A' ¶        // → 65    字符的码点
```

```zymbol
圆周率 = 3.14159265
>> #.2|圆周率| ¶       // → 3.14          四舍五入到 2 位小数
>> #!2|圆周率| ¶       // → 3.14          截断到 2 位小数
>> #,|1234567| ¶   // → 1,234,567     千位分隔符
>> #^|12345.678| ¶ // → 1.2345678e4   科学记数法
```

```zymbol
>> 0x41 ¶        // → A   十六进制
>> 0b01000001 ¶  // → A   二进制
>> 0o101 ¶       // → A   八进制
>> 0d65 ¶        // → A   十进制
```

> ASCII 范围内的基数字面量是一个 **字符**：`0d65 == 'A'` 是 `#1`，而 `0d65 == 65` 是 `#0`。所有四种基数都表示同一个字符。

## 符号如何组合

你在本手册中一直在看到同样的事情：**操作符不是需要记忆的图形，而是连续排列的多个符号，每个符号都贡献其含义。** 既然你已经了解了所有符号，这里就是完整的模式。

首先是 **我们在哪个世界**：

| 符号 | 世界 | 你在哪里见过 |
|------|------|-------------|
| `$` | 集合 | `$#` `$+` `$?` `$^-` |
| `@` | 时间，重复的事物 | `@!` `@>` `@~` |
| `#` | 事物 *是什么*，而不是它的值 | `#?` `#(…)` `<#` `#>` |
| `>>` | 从程序输出 | `>>` `>>!` `>>?` |
| `<<` | 向程序输入 | `<<` `<<\|` `<<\|?` |
| `?` | 询问，不承诺 | `?` `_?` `??` `$?` |
| `!` | 强制，或错误 | `@!` `$!` `!?` |

然后是 **在那里做什么**：`+` 添加，`-` 移除，`^` 排序，`~` 修改，`#` 计数，`|` 单个单元，`:` 绑定名称。

还有两条不会出错的规则：

**重复一个符号使其穷举。** `?` 询问一次，`??` 测试多种情况。`$?` 询问值是否存在，`$??` 返回每个存在的位置。`!` 标记错误，`!!` 不问即传播。

**模式符号总是放在最后。** 当 `?` 或 `!` 出现以说明 *如何* 执行操作 — 试探性地还是强制性地 — 它们是操作符的最后一个符号：`$??`、`$!!`、`<<|?`、`@!`、`##!`、`>>!`、`>>?`、`@:外部!`。它们之后从不会有另一个操作。

由此产生了一个实际的结果：**一个你从未见过的组合，在你查阅之前就已经有了意义。** 如果 `$` 是集合，`^` 是排序，`-` 是反向，那么 `$^-` 就是降序排序，没有人需要告诉你。

并非所有的符号表都这样工作，说出来比假装要好。大多数操作符可以清晰地分解。有六个可以分解但含义超过其部分之和：`!?` `:!` `:>` `|>` `::` `$++`。还有十个必须死记硬背，因为它们根本不能分解：`¶` `><` `#1` `#0` `0x` `0b` `0o` `0d` `###` `°`。

> 计数不透明的符号而不是假设它们很少，这是故意的：它们是语言真正的记忆成本。完整的参考 — 符号表、声明的同形异义词以及新操作符必须满足的规则 — 位于解释器仓库的 `SYMBOLS.md` 中。
