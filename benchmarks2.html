How fast is Zymbol?

Sixteen programs, eight languages and four Zymbol engines, the same printed answer. Pick any of them as the reference and the rest is measured against it. One machine, elapsed time per process — and the programs, their twins and the script that measured them are public.

Program by program

Zymbol, Lua, PHP, Ruby, Python and Perl are interpreters: they run the program without turning it into machine code. PHP's opcache JIT is off on the command line and Ruby's YJIT is off without --yjit, so both run here as interpreters. JavaScript (Node, V8) and Julia, marked JIT, compile to machine code while they run, and are here as the reference of what compiling buys. Julia starts in 163 ms before running anything: on programs this short, start-up is a large part of its figures — subtract it and Julia comes to 0.19× of Zymbol, next to JavaScript's 0.12×.

Said plainly, with Zymbol v0.0.11 as the reference: Zymbol is the third fastest of the six interpreters. Lua is faster on 13 of the sixteen and PHP is faster on 13 of the sixteen — mature virtual machines with decades of tuning behind them, and Lua's is a register machine like Zymbol's; they are the bar now. Zymbol is ahead of Ruby, Python and Perl in the mean, and still behind one of them on a few programs: Ruby on collatz, fib_rec, matmul, nqueens, primes_trial, tak; Python on fib_rec, tak; Perl on hof_chain, matmul, sort_cmp_300k, sort_cmp_4k. With start-up subtracted, PHP (0.37×), Lua (0.43×) and Ruby (0.80×) are ahead of it. The deep-recursion programs, fib_rec and tak, are where a call still costs Zymbol most, and that is the next thing being worked on.

What went into the interpreter between the two commits:

  • the tree-walker's value shrank from 120 to 24 bytes: a function and an error moved into a box (ZYTW-019)
  • a call's result is let go when its statement ends, unless arithmetic showed it is a number (ZYVM-022) — memory, for 0.05 % of the VM's steps
  • a position in a text that is not ASCII is found from a crumb every 64 characters (GLB-139) — none of the sixteen programs indexes such a text
  • an edit two levels down is written in place in the tree-walker (GLB-140) — none of the sixteen programs does one
  • std/db stopped being a default feature (D4); the binary measured here is built with it, as the earlier one was

What changed in the VM, in short: a counted loop and a for-each that end each turn in one instruction, $> $| $< calling their lambda on the VM's own frames, a sort comparator that is a plain comparison evaluated without a call, an assignment written by the instruction that computes it, a text that keeps its character count, a dictionary found by a fast seeded hash, and a call that stopped paying for work it did not need. Nothing in the language changed: every program prints what it printed.

  • Twins. Each program is written once per language with the same algorithm and the same shape as the Python twin, and its printed line is compared with Python's before any figure is kept — 176 of 176 agree. Julia's twins put their code inside a main() function: a global in Julia is untyped, and measuring that would measure a use nobody writes.
  • Elapsed time — what whoever runs the program waits — median of 5 runs of the whole process on an otherwise idle machine: start-up, parsing, compiling and running. CPU time was recorded too and agrees with it for the interpreters, which run on one thread; not for the JIT compilers, which compile on other threads while the program starts — Julia used 2.9× as much CPU time as elapsed time. An earlier version of this page showed CPU time, and charged Julia for work no one waits for.
  • Start-up subtracted takes each language's empty-program time off every figure — the reference's too — over the programs Zymbol v0.0.11 takes 100 ms or more on; on shorter ones, subtracting two close figures would be noise.
  • Not a ranking of languages. Sixteen small programs say how fast an interpreter runs loops, calls, arithmetic, collections and text — not how fast real applications are, which depend on libraries this does not touch.
  • v0.0.11 is not released yet. These are figures of its development branch (commit 52ad7d3); the release notes will carry the final ones.
